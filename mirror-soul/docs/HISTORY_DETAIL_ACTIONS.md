# 통화 기록 상세의 전화·더보기

2026-10-05. RN만 수정. 백엔드·AI·인프라 코드와 API 계약은 변경하지 않았다.

## 전화 버튼

발신·수신·전체 기록의 공통 상세 화면에서 `GET /history/calls/{call-id}/talk-logs`의 `partner.userUuid`와 이름을 사용한다. 수신 기록에서도 원래 발신자의 **AI 트윈**에 새 통화를 거는 것이며 실제 회원에게 전화하지 않는다.

- 기존 `CallStartConfirmSheet`로 최신 `GET /my-page/buy-time` 잔액을 확인한다. 잔액 미확인·조회 실패 상태로 통화를 시작하지 않는다.
- 0초면 같은 native Modal 안에서 기존 테스트 충전 UI로 전환한다. Android 뒤로 가기·닫기는 통화 기록으로 돌아온다.
- 명시적으로 시작하면 대상 UUID·이름·확인한 남은 초를 `/ai-call`로 전달한다. 기존 `useAICallFlow.startCall()` → `initiateCall()` → `POST /calls/clones/{uuid}`(현재 AI 트윈 통화의 `VIDEO` 설정) 흐름을 재사용한다. 상세 버튼에서 별도의 통화 생성 POST를 중복 호출하지 않는다.
- 통화 API는 잔액, 클론 존재 여부, 상대 ACTIVE·매칭 허용 상태 및 양방향 차단을 판정한다. 과거 기록이 있다고 현재 통화가 가능하다고 보장하지 않는다. 서버/AI 연결 실패는 기존 통화 화면의 복구 흐름을 따른다.
- 답변 수정·저장·기록 갱신 중에는 전화 버튼을 비활성화한다. 연속 시작은 동기 락을 쓰며, 확인 창을 닫은 뒤 이동한다. 화면 이탈·언마운트·다른 callId 진입은 예약된 이동을 취소한다.
- 부정확한 상대 식별자나 잘못된 기록 ID로 통화하지 않는다. 기록 조회 훅도 양의 안전한 정수 ID만 요청한다.

## 더보기 UI

햄버거 버튼의 실제 위치에 붙는 팝오버 메뉴를 제공한다. 선택된 버튼의 옅은 배경과 연결 표시로 메뉴의 출처를 알린다. 닫기·새로고침·전화·햄버거는 같은 선형 아이콘, 전화·햄버거는 같은 48px 버튼을 사용한다. 별도 native Modal을 추가하지 않는다.

| 항목 | 동작과 실제 데이터 |
| --- | --- |
| 사용자 상세 보기 | 기록 API의 상대 UUID로 기존 공개 상세 모달과 `GET /home/recommendations/{uuid}`를 재사용. 최신 응답을 정본으로 사용하며 조회가 거절되면 안내와 기록 복귀 제공 |
| 통화 정보 | 기록 API의 상대 이름·나이·사진, 서버가 만든 대화 설명, 시작 일시·통화 회차, `editable`인 답변 개수 |
| 기록 새로고침 | 현재 callId의 기존 조회 쿼리를 다시 실행. 수정/저장 중 비활성화, 실패 시 재시도·기록 복귀 제공 |
| 기록 안내 | 지난 대화의 텍스트 기록, 내 트윈의 수정 가능한 답변, 수정한 내용은 기록에 저장됨, 전화는 상대 AI 트윈과의 새 통화라는 안내 |
| 사용자 신고하기 | 사유 선택 → 기존 앱에 설정된 문의 주소 `mirrorsoul64@gmail.com`으로 메일 초안 열기. 사용자가 메일 앱에서 직접 전송하며 접수 완료로 표시하지 않음 |
| 사용자 차단하기 | 영향 확인 → 기존 `POST /blocks/{uuid}` 호출. 성공 후 기록 탭으로 복귀, 실패 시 기록 유지 및 재시도 안내 |

프로필 응답이 오기 전에는 기록의 이름·나이·사진만 임시로 사용하며 성향·소개·음성을 만들어 표시하지 않는다. 총 통화 길이·매체도 기록 상세 응답에 없는 값을 추정하지 않는다. 삭제·기록 공유는 제공하지 않는다.

신고 API는 현재 없다. 신고 사유 5종 중 선택한 값, 상대 UUID·이름·통화 ID만 초안에 포함하며 대화 원문·음성은 자동 첨부하지 않는다. 세부 내용은 메일 작성 화면에서 입력한다. 메일 앱 열기 실패 시 선택한 사유를 유지하고 받는 주소를 보여준다. 이 주소는 기존 RN 설정을 재사용한 것이며 운영 접수·처리 시간을 보장하지 않는다.

차단 성공 후 추천 페이지와 페이지 경계를 유지한 채 상대만 제외한다. 채팅방·받은 신청·통화 목록에서도 제거하고, 상대 상세 캐시를 삭제하며 집계는 서버에서 다시 확인한다. 진행 중인 조회를 취소하여 이전 응답이 상대를 복원하지 않게 한다. 서버 실패 시 캐시는 변경하지 않으며, 요청 도중 계정이 바뀌면 새 계정 캐시나 화면 이동에 영향을 주지 않는다. 본인 차단/신고와 답변 수정 중 전화·새로고침·사용자 상세·신고·차단은 막는다.

헤더의 전화·메뉴 터치 영역은 각각 48px이며 서로 겹치지 않는다. 이름·설명·통화 회차는 한 줄 말줄임으로 표시하고 스크린리더에는 전체 이름을 제공한다. 작은 화면·큰 글자에서는 장식용 아바타를 숨기고 이름과 행동 공간을 확보한다. 메뉴는 화면 루트 기준으로 측정한 버튼 좌표·화면 크기·좌우 안전 영역으로 위치와 높이를 제한한다. 아래 공간이 부족하면 위쪽에 열고, 내용이 길면 메뉴 안에서 스크롤한다. Android 뒤로 가기는 정보/안내/신고 → 메뉴 → 기록 순서로 닫는다. 메뉴가 열리면 배경 화면은 스크린리더 탐색에서 제외한다.

## 상대 전체 프로필 조회에 대한 백엔드 협의

`RecommendationDetailService.getDetail()`은 ACTIVE·매칭 허용·양방향 차단 조건에 더해 **최근 추천 노출 이력**을 요구한다. 따라서 기록의 상대 UUID가 유효해도, 특히 내 트윈과 통화한 회원이 내 추천에 노출된 적 없으면 `GET /home/recommendations/{uuid}`가 거절된다. 메뉴에서 상세를 요청하되 이 경우 조회 불가 안내와 기록 복귀를 제공한다. 권한을 우회하거나 빈 정보를 전체 프로필로 가장하지 않는다.

통화 상대 전체 프로필을 추천 노출 이력과 독립적으로 제공하려면 아래 계약이 필요하다.

| 요청 사항 | 권장 일관성 |
| --- | --- |
| 기록 상대 프로필 조회 | 예: `GET /history/calls/{callId}/partner-profile`. 현재 회원이 그 완료된 통화의 당사자인지 확인하고 상대를 서버에서 결정 |
| 접근·공개 정책 | ACTIVE·매칭 허용·양방향 차단 정책을 추천·채팅·통화 기록 사이에서 명시적으로 통일. 추천 노출 이력과 통화 참여 이력을 각각 어떻게 허용할지 합의 |
| 응답 모양 | 기존 `RecommendationDetailDTO`와 동일한 공개 필드·사진·성격·음성 상태/URL 계약을 재사용. 학습 원본·직업 서류·사적인 통화 내용을 공개 프로필에 포함하지 않기 |
| 현재 통화 가능 여부 | 필요하면 대상 준비/접근 상태와 불가 사유를 명시적으로 제공. 과거 통화나 싱크로율만으로 RN이 추정하지 않기 |

이 표는 API 제안이며 서버 코드를 구현하거나 권한을 우회하지 않았다.

정식 신고 접수를 위해서는 신고 생성 API(예: `POST /reports`)에 대상 UUID, 선택적 callId/chatRoomId, 일관된 reasonCode, 설명을 받고 reportId와 접수 상태를 반환하는 계약이 필요하다. 서버에서 신고자의 대상 접근 권한·본인 신고 금지·중복/남용 제한을 검증하고, 운영자 처리/알림 정책을 정해야 한다. 문의 주소의 운영 여부도 확정해야 한다.

## 확인할 흐름

1. 전체·발신·수신 각 탭 → 상세 → 전화 → 최신 잔액 확인 → 취소 / 시작.
2. 0초 → 충전 창 → 닫기 / Android 뒤로 가기 → 기존 기록 유지.
3. 더보기 → 통화 정보 / 기록 안내 → 뒤로 → 새로고침.
4. 내 트윈 답변 수정 중에는 전화·새로고침 차단, 저장·취소 후 정상 복구.
5. 작은 기기·가로 화면·큰 글자에서 두 헤더 버튼과 메뉴 마지막 행 접근.
6. 대상 비활성·차단·클론 없음·잔액 조회 실패, 상세 조회 실패의 복구.
7. 긴 닉네임·320px 화면·큰 글자·가로 화면에서 버튼 유지, 더보기와 연결 표시, 마지막 행 스크롤 접근.
8. 사용자 상세 조회 성공 / 추천 노출 이력이 없어 거절 / 기록 복귀.
9. 차단 취소 / 실패 / 성공, 차단 후 추천·기록·신청·메시지에서 제외 확인.
10. 신고 사유 선택 → 메일 앱 작성/전송, 메일 앱 미설정 오류 및 사유 유지.

컴포넌트 테스트와 번들 검증은 실제 기기의 터치·줄바꿈·서버/AI 음성 연결 검증을 대체하지 않는다.
