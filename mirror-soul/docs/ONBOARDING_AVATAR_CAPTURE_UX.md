# 가입 마지막 단계: 아바타 촬영 UX

## 범위와 결정

RN만 수정한다. 백엔드·AI·인프라 구현과 submodule 포인터는 변경하지 않는다. 기존 가입 브랜치 `codex/onboarding-profile-personality-ux`에서 진행한다.

사용자 결정: 위·아래 촬영 제거, 편안한 정면·가벼운 미소·말하는 모습·좌우 움직임을 약 20~25초에 담기. 말하기에는 짧은 예시 문장을 사용하고 영상의 소리는 저장하지 않는다. 어깨까지 담는 안내를 제공하며 자동으로 어깨가 확인됐다고 표시하지 않는다.

## AI 입력 분석

분석 대상은 로컬 AI `ed4409d`, 백엔드 `cded928`의 소스다. 배포 서버와 동일하다는 의미는 아니다. AGENTS.md에 명시된 `.Codex/artifacts/backend-schema.json`, `analysis-report.md`는 현재 체크아웃에 없어 관련 서비스만 직접 읽었다.

- `mirror-soul-AI/model_training/face_training/video_processor.py`: 기본 1~120초 영상, 최소 한 축 256px, 2fps/최대 120프레임 추출. 프레임은 얼굴만 잘라 저장하는 방식이 아니므로 촬영한 어깨 구도를 유지할 수 있다.
- `frame_analyzer.py`: 얼굴 수·선명도·밝기·대비·얼굴 크기·중심 위치 등을 평가한다. 정면·좌측·우측 대표 프레임을 선택하며 위·아래 구간을 필수로 검증하지 않는다. 정면 중 품질 점수가 좋은 프레임이 portrait 후보가 된다.
- `natural_motion.py`: 사용자의 자연스러운 움직임을 포함한 연속 구간을 품질과 정면 비율로 선택한다. 기본 정면 비율 기준은 60%다.
- `worker.py`, `profile_artifacts.py`: 현재 주 경로는 정면 portrait와 렌더 설정을 포함하는 통화용 얼굴 프로필 생성이다. 미소·말하기를 각각 태깅해 사용자별 얼굴 모델의 별도 가중치를 학습하는 구조는 아니다. 선택한 원본 영상의 움직임을 활용하는 경로도 있으나 실제 활성 옵션과 렌더 결과는 별도 검증해야 한다.
- AI 소스에서 어깨 검증 규칙은 찾지 못했다. 얼굴과 어깨를 함께 담는 안내는 프레임 구도를 위한 권장 사항이다.

따라서 정면 시간을 충분히 확보하고, 미소·말하기·작은 좌우 움직임을 안내하는 RN 변경은 현재 입력 형식과 호환된다. 학습 효과나 사용자 고유 말투/표정이 그대로 재현된다는 보장은 하지 않는다. 미소나 입을 벌린 프레임이 최고 품질 portrait로 선택될 수도 있다. 정면 기본 사진을 항상 무표정으로 선택하려면 향후 AI의 중립 표정 우선 선택/구간 태그 계약이 필요하다.

## 촬영 흐름

1. 카메라 열기: 목적·예상 시간·소리 미저장·공개 프로필 사진과 별개라는 안내.
2. 전체 화면 미리보기: 얼굴·어깨 윤곽에 맞추기. 카메라 출력 비율을 유지하며 남은 공간에 맞추고 가입 진행률은 촬영 모달 밖에 둔다.
3. 한 명의 얼굴이 구도 안에 있고 정면인 경우에만 3초 준비 버튼 활성화. 준비 중 얼굴이 사라지면 구도 확인으로 돌아간다.
4. 유효 프레임 시간 기준으로 아래 구간 진행. 얼굴 미검출·다중 얼굴·구도/각도 불일치 동안 구간 진행을 멈춘다. 영상 자체는 연속 녹화되며 잘못된 구간을 RN에서 편집해 제거하지 않는다.
5. 촬영 종료 후 사용자가 `영상 등록하기`로 확정. 자동 업로드하지 않는다. 다시 촬영도 가능하다.
6. S3 전송률과 서버 등록 대기를 구분. 실패 시 촬영 파일 유지, 서버 등록 재시도 시 이미 PUT한 파일은 다시 업로드하지 않는다.
7. 서버 등록이 확인되면 `트윈을 준비하고 있어요` 표시. 가입 완료와 AI 작업 완료를 구분한다. `상대 둘러보기`에서 로컬 ACTIVE 동기화 후 홈으로 이동한다.

| 구간 | 유효 시간 | 안내 |
| --- | ---: | --- |
| 편안한 정면 | 4초 | 정면을 보고 편하게 있기 |
| 가벼운 미소 | 3초 | 평소처럼 살짝 웃기 |
| 말하는 모습 | 7초 | “안녕하세요. 만나서 반가워요.” 편하게 말하기 |
| 왼쪽 | 2초 | 살짝 돌리기 |
| 오른쪽 | 2초 | 살짝 돌리기 |
| 다시 정면 | 3초 | 편안한 기본 모습으로 끝내기 |

유효 시간 합계 21초, 준비 3초. 얼굴을 맞추거나 고개를 전환하는 시간에 따라 25초보다 길어질 수 있음을 안내한다. 정면 유효 시간은 17초로 약 81%다. 60초 이상 진행되지 않으면 안전하게 재시작을 안내한다.

미소와 발화는 안내에 따라 담으며 실제 웃음/발화·문장 내용은 검증하지 않는다. 얼굴 인식은 신원 인증이나 본인 여부 검증이 아니다. `audio=false`이므로 영상용 마이크 권한을 추가 요청하지 않는다.

## 레이아웃과 접근성

- 기존 460px 고정 카메라와 큰 외부 여백을 제거했다.
- 촬영 카메라와 안내·버튼을 분리하고 카메라 위 얼굴 영역에는 문구를 올리지 않는다. 준비 카운트다운만 일시적으로 표시한다.
- 실제 사용 가능한 영역과 영상 비율로 카메라 크기를 산출한다. 촬영은 앱의 기존 세로 방향 설정을 따른다.
- 일반 글자 크기에서 촬영 화면은 스크롤하지 않는다. 접근성 글꼴 배율 1.4 초과에서는 안내·버튼 영역만 제한 높이로 스크롤할 수 있게 한다. 안내 확인 모달과 가입 소개는 필요하면 스크롤할 수 있다. 모든 극단적인 창 크기·글꼴 설정에서 무조건 스크롤을 없앤다고 보장하지 않는다.
- 버튼 최소 높이 48px, 안내 링크 44px, 줄바꿈 가능한 텍스트, 명시적인 취소, 진행률 접근성 값을 제공한다. 오류 문구는 테마의 danger 색상 사용.
- MLKit의 미리보기 좌표 변환, 전면 카메라의 좌우 Euler 각도 및 전환 임계값은 실제 iOS/Android 기기에서 확인이 필요하다. 어깨 윤곽은 구도 가이드이며 인식 결과가 아니다.

## 오류·데이터 일관성

- 카메라 미리보기가 준비되기 전에 녹화하지 않는다. 권한 거절에는 설정 링크, 카메라 준비 15초/영상 마무리 10초 지연에는 재시작 경로를 제공한다.
- 오래된 얼굴 프레임으로 시간이 누적되지 않도록 프레임 간격/최근 감지 시간을 검사한다. 검출은 5fps로 제한하고 옵션은 측정 크기가 바뀔 때만 재생성한다.
- 앱 비활성화·백그라운드·전화 등 인터럽트와 계정 변경 시 촬영을 취소한다. iOS 카메라 권한 팝업의 정상 inactive는 촬영 시작 전 별도로 처리한다.
- 촬영별 식별자로 오래된 네이티브 콜백을 무시하고 미완료 파일을 폐기한다. 모든 구간이 끝나고 정상 종료된 20초 이상 영상만 등록 후보가 된다.
- `stopRecording`/`cancelRecording` 비동기 예외를 회수한다. 언마운트 시 타이머·AppState·인증 구독을 정리한다.
- mp4/H.264, 약 3Mbps, 선호 1280×960·30fps로 촬영한다. 실제 카메라가 지원하는 가장 가까운 형식을 선택하므로 이 해상도를 보장하지 않는다. 출력 파일의 실재·비어 있지 않음·100MiB 이하를 업로드 전에 확인한다.
- 등록 잠금과 세션 검증으로 중복 탭/이전 계정의 작업을 막는다. 응답의 saved, objectKey, userUuid를 모두 확인한다.

### 서버 응답 유실

`VisualService.saveVisualFile`은 ONBOARD_D만 허용하고 영상 등록 및 작업 생성 후 즉시 ACTIVE로 변경한다. 같은 POST가 서버에서 성공했으나 응답을 받지 못했다면 재시도가 AUTH_4030으로 거절될 수 있다. 현재 응답 유실을 정확히 확인할 읽기 API/멱등 계약은 없다. 거절을 임의의 성공으로 처리하지 않는다. RN에서는 `다시 로그인하여 확인`을 제공하여 로그인 응답의 실제 userStatus로 복구한다. 서버 등록이 되지 않았다면 가입 마지막 단계로 돌아갈 수 있으나, 로그인 과정에서 로컬 미완료 파일은 유지되지 않는다. 서버 수준의 멱등 등록이나 등록 조회가 향후 개선점이다.

## 검증 및 실기기 확인

자동 검증은 훅·화면의 모의 네이티브 환경에서 수행한다. 실제 카메라 센서, MLKit 좌표, 파일 코덱, 소리 미저장, AI 출력, 폰별 글꼴 및 안전 영역을 검증한 것은 아니다. MLKit arm64 시뮬레이터 제약이 있어 이 환경에서는 iOS 시뮬레이터 검증 대신 실기기 확인이 필요하다.

실기기 권장 확인: 작은 화면과 큰 화면의 iOS/Android, 큰 글자·디스플레이 확대, 카메라 권한 처음 허용/거절, 좌우 방향 안내, 어깨를 담은 정상 거리, 웃기·말하기 도중 검출 유지, 검출 끊김과 여러 사람, 앱 전환/전화/잠금, 빠른 취소·재시작, 업로드 실패→재시도, 등록 후 로그인 복구. 영상의 실제 파일 정보와 AI portrait/자연스러운 움직임 결과도 함께 확인한다.

자동 검증 결과: 새 회귀 테스트 4묶음·41개 통과, 전체 45묶음·292개 통과. 새 변경 파일의 ESLint 및 TypeScript 진단 없음(프로젝트 전체의 기존 TypeScript 오류는 남아 있음). iOS·Android Expo production JS/Hermes 번들 생성 통과. Jest 전체 실행에는 기존 종료 대기 문제를 피하기 위해 `--forceExit`를 사용했다. 새 촬영 훅 테스트는 fake timer·네이티브 모의 환경이며 실제 촬영/모든 기기의 시각적 배치를 보장하지 않는다. 라이브러리나 네이티브 설정을 바꾸지 않아 재-prebuild/Pods 설치는 필요하지 않다.
