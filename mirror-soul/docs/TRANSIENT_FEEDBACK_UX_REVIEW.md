# 일시적 알림 UI 조사·개선

2026-10-06, `codex/call-entry-connected-ux`. RN만 수정했다. 실제 기기의 화면을 캡처하거나 겹침을 재현한 결과가 아니라, 사용자 제보와 RN 구현을 기준으로 확인했다.

## 지역 저장 알림의 공통 원인

`discovery-region-settings.tsx`는 저장 성공 후 `showToast('탐색 지역을 저장했어요.', 'success')`와 `router.back()`을 연이어 실행한다. 알림 문구 자체의 문제가 아니라 공통 ToastProvider의 표시 구조에 문제가 있었다.

- 배경이 `colors.background.glass`여서 전환 중인 화면의 제목·본문이 비칠 수 있다.
- Date.now() key의 새 알림을 FadeInDown으로 넣고 이전 것을 FadeOutUp으로 내보내므로 교체 동안 두 알림이 같은 영역에 존재할 수 있다. 같은 시간 값의 메시지도 확실히 구분하지 못한다.
- 모든 문구를 3줄·3초로 제한해 긴 실패 안내나 큰 접근성 글자를 읽기 어렵다.
- 일반 View의 zIndex만으로는 다른 native Modal 위에 표시할 수 없다. 시트를 유지하는 실패 안내가 시트 뒤에 가려질 수 있다.
- 전역 ToastContext에 매 렌더 새로운 객체를 제공해 알림과 관계없는 화면 소비자도 갱신될 수 있었다.

## 같은 UI를 사용하는 범위

| 기능 | 대표 알림 | 처리 |
| --- | --- | --- |
| 탐색 지역 | 저장 성공, GPS 조회 실패, 위치 권한 안내, 저장 실패 | 공통 카드로 표시. 성공 후 이전 화면에서도 이어서 표시 |
| 사진·닉네임 | 프로필 사진 등록/삭제, 닉네임 변경 성공 | 같은 카드. 열린 편집 창과 닫힌 화면 사이에서 단일 알림을 전달 |
| 대화 시간 | 테스트 충전 완료, 충전 실패, 약관 링크 열기 실패 | 열린 바텀시트의 native 레이어에서 표시. 기존 결제/테스트 충전 문구 유지 |
| 발견·매칭 | 매칭 상태 저장 실패, 신청 거절·처리 실패 | 공통 카드. 연속 알림은 최신 하나만 유지 |
| 기록 | 답변 수정 실패, 차단 완료/실패, 새로고침 실패, 메일 앱 열기 실패 | 공통 카드. 성공과 실패는 아이콘/색으로 구분 |
| 음성·알림 설정 | 목소리 크기·일반 알림 설정 저장 실패 | 공통 카드 |
| 대화방별 알림 | 대화방 알림 관리·대화방 옵션에서 저장 실패 | 이미 제공하는 화면 안 오류를 유지하고 같은 내용의 토스트는 생략 |
| 계정·세션 | 탈퇴 실패, 계정 변경, 세션 만료 후 로그인 안내 | 공통 카드. React 밖 apiClient의 showGlobalToast 경로도 유지 |
| 가치관 게임 | 답변 제출 실패 | 시트 하단 FloatingNotice 대신 공통 카드로 통일. 버튼을 덮는 두 번째 알림 제거 |

회원가입 폼·닉네임 검증·사진 업로드 오류 등 **수정할 입력이 명확한 오류**는 해당 입력/행동 가까이에 남긴다. 사진 편집 종료·변경 내용 폐기·마이크/카메라 권한 같은 **선택이 필요한 안내**의 Native Alert를 자동으로 사라지는 성공 알림으로 바꾸지 않는다.

기존 FloatingNotice/useFloatingNotice 파일은 공개 API 보존을 위해 남겼으나 앱 화면에서 직접 사용하는 경로는 이제 없다.

## 새 표시 방식

- 불투명 배경·중립 테두리·작은 상태 아이콘·문구·44px 닫기 버튼을 한 카드로 구성한다. 그림자는 가볍게 사용하고 움직이는 진입/퇴장 효과를 제거했다.
- 문구와 아이콘/닫기의 공간을 분리하고 앱의 SUITE/Pretendard 본문 글꼴을 사용한다. 줄 수를 제한하지 않고 메시지가 너무 길면 카드 안에서 스크롤한다.
- 성공/정보/오류의 기본 표시 시간은 각각 4/5/6초다. 문구 길이와 글자 확대에 따라 최대 12초까지 늘린다.
- 알림을 만지거나 스크롤하면 자동 종료를 멈추고 사용자가 닫게 한다. 스크린리더가 켜졌을 때도 자동 종료하지 않는다.
- 동일한 시간에 여러 메시지가 와도 고유 순번으로 교체하고 **최신 한 개만** 표시한다. 이전 타이머가 새 메시지를 지우지 않게 한다.
- ToastViewport는 기존 native Modal의 전체 오버레이 안에서 표시한다. 추가 Modal을 열지 않는다. 공통 BottomSheet, 닉네임 변경, 사진 편집, 대화방 알림 관리에 연결했다.
- 창이 닫히면 아직 유효한 메시지를 다음 표시 영역으로 넘긴다. 화면/모달 간 동시에 두 카드가 보이지 않도록 메시지의 현재 표시 영역을 관리한다.
- 안정된 API context와 표시 상태 context를 분리했다. 알림을 띄운다는 이유만으로 useToast 소비자가 전부 재렌더되지 않도록 한다.
- 상단 안전 영역과 좌우 인셋을 적용하며, 카드 높이는 실제 오버레이 높이에 맞춰 제한한다. 아이콘은 글자 확대와 별도로 고정 크기를 유지해 문구를 침범하지 않는다.

## 검증과 실제 기기 확인

- 전체 Jest 103개 묶음·705개 테스트 통과 (`--forceExit`, 기존 SDK/테스트 타이머 때문에 사용).
- 마지막 표시 조정 관련 2개 묶음·14개 테스트 통과. 같은 시각의 연속 메시지, 이전 타이머, 읽기 중 유지, native 모달 표시 영역/닫기 후 전달, 스크린리더 유지, 240px/가로/태블릿·큰 글자를 검증했다.
- 변경 파일 ESLint 및 새 타입 오류 검사 통과, iOS·Android Metro/Hermes 번들 생성 통과. 기존 전체 TypeScript 오류는 작업 범위 밖에 남아 있다.
- 컴포넌트 테스트의 메시지/계층 검증은 실제 Yoga 배치·native 모달 z-order·VoiceOver/TalkBack을 대신하지 않는다.

실기기 확인 순서:

1. 지역 저장 → 발견으로 복귀: 알림 아래 글자가 비치지 않고 한 카드만 보이는지.
2. 알림 닫기·긴 오류 스크롤·연속 메시지 교체·화면 회전.
3. 작은 iPhone/Android, 큰 글자, VoiceOver/TalkBack에서 문구와 닫기 버튼 접근.
4. 충전/가치관/약관 링크 오류를 시트를 닫지 않고 확인할 수 있는지.
5. 사진·닉네임 성공 후 창이 닫혀도 알림이 정상적으로 이어지는지.
6. 대화방 알림 저장 실패가 화면 내 오류 한 번만 표시되며 기존 확인된 토글 값이 유지되는지.
