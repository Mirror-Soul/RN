# 직업 서류 심사 RN 연동

기준: 백엔드 main `c1deb11` (PR #201), RN 작업 브랜치 `codex/job-verification-review-ux`.

## 결정 사항

- 직업 서류 심사와 PASS 본인확인은 별개다. 승인된 제출 자료는 공개 프로필에 **직업 서류 확인**으로 표시한다.
- 상세 프로필에 서류 확인의 범위와 PASS 본인확인·서류 명의 대조까지 완료된 인증은 아니라는 안내를 제공한다.
- 가입 중 서류는 선택이다. 미제출·실패한 경우 가입을 먼저 마치고 성장 탭에서 제출할 수 있다.
- 사진 1장부터 시작하고 필요한 경우 최대 5장까지 추가한다.

## 연결한 API

1. `POST /files/presigned-url`, directory `job-certifications`, Content-Type `image/jpeg`.
2. S3에 실제 JPEG를 PUT한다. HEIC 등의 이미지는 네이티브 디코더로 JPEG를 만들며 서류를 4:5로 자르지 않는다. 사진당 5 MiB 제한을 적용한다.
3. `POST /job-verifications`의 objectKeys 배열로 심사를 접수한다. 업로드만으로 접수 완료 표시를 하지 않는다.
4. `GET /job-verifications/me`로 최신 요청과 반려 사유·현재 직군 일치 여부를 표시한다.

가입에서는 직군을 서버에 저장한 다음 접수한다. 프로필 저장 후 접수만 실패하면 프로필을 다시 저장하지 않고 서류만 재시도한다. 가입을 먼저 계속하면 같은 세션의 사진과 업로드 키를 성장 화면에서 다시 사용할 수 있다.

## 화면과 복구

- 가입·성장에 공용 사진 첨부 기능: 선택/촬영, 추가, 확대 보기, 교체, 초안 삭제.
- 제출 버튼은 상태 조회 성공 이후에만 활성화한다. 조회 실패를 미신청으로 대신 표시하지 않는다.
- PENDING: 확인 중. APPROVED: 서류 확인 완료. REJECTED: 보완 사유와 재제출.
- 현재 직군과 다른 대기 요청은 새 제출을 막고 현재 심사 종료를 안내한다. 서버에 철회 API가 없으므로 임의의 취소 버튼을 제공하지 않는다.
- 접수 요청 응답이 유실되면 동일한 S3 키/순서로 재시도한다. 일부 사진만 전송됐다면 성공한 사진을 다시 올리지 않는다.
- 전송 진행률은 사진별 실제 전송량과 준비된 파일 크기를 기준으로 계산하고, 사진 전송과 서버 접수 대기를 구분한다.
- 사진 초안은 메모리에만 보관한다. 로그아웃/계정 변경/직군 변경/접수 성공 시 정리하며, 앱 재시작 후까지 초안 복구를 보장하지 않는다.
- 서류 이미지는 디스크 이미지 캐시를 사용하지 않는다. 사진 준비 과정에서 만든 임시 파일만 정리하며 사용자 원본을 삭제하지 않는다.
- 추천 카드·상대 상세·내 공개 미리보기는 `jobDocumentReviewCompleted === true`일 때만 서류 확인 표시를 제공한다. legacy `jobCertificationSubmitted`로 승인 배지를 만들지 않는다.
- 반려 사유는 한 줄로 생략하지 않는다. 본문은 스크롤하고 하단 버튼은 별도로 배치한다. 짧은 화면·가로 화면·큰 글자에서 바텀시트가 화면 높이를 넘지 않게 한다.
- 사진 준비·전송·접수 중 바텀시트의 드래그/배경/Android 뒤로 가기 종료를 막는다.

## 알림

- 서버의 `/job-verifications` 푸시 경로에 대응하는 RN 화면을 추가했다.
- 직업 심사 결과를 누르면 로그인·가입 완료를 기다렸다가 결과 화면으로 이동한다. 이전 계정에 묶인 보류 알림은 다른 계정으로 넘기지 않는다.
- 포그라운드 결과 알림, 성장/결과 화면 진입, 앱 복귀에서 최신 상태를 조회한다. 성장 화면의 PENDING 조회는 기존 90초 제한 갱신 방식을 활용한다.
- 개별 직업 결과 알림 ON/OFF 필드는 백엔드에 없으므로 작동하지 않는 토글을 추가하지 않았다.
- iOS 푸시 토큰 등록은 기존 설정대로 Android 전용 가드가 유지된다. 실제 iOS 푸시는 기존 유료 개발자/APNs/네이티브 capability 설정을 준비해야 하며 이번 RN 수정에서 활성화했다고 주장하지 않는다. 푸시가 없어도 화면 진입/복귀 조회로 확인 가능하다.

## 운영·백엔드 확인 사항

- API 명세 공개 조회는 분석 당시 HTTP 502였다. 원격 코드 병합은 확인했지만 실제 운영 배포·로그인 요청은 확인하지 못했다.
- V42/V43/V44 마이그레이션, 관리자 계정·사진 조회 S3 권한/CORS, Firebase 발송 조건을 배포 환경에서 확인해야 한다.
- 관리자 웹은 이 변경에 포함하지 않는다. 기존 backend 관리자 대기 목록/사진 상세/승인/거부 API로 별도 운영 화면을 만들 수 있다.
- legacy 직업 사진은 새 심사 요청으로 자동 전환되지 않는다. RN은 제출 이력이 없었다고 단정하는 문구를 사용하지 않는다.
- 제출 후 사진 조회/신청 철회·가입 후 직군 수정·직업 결과 알림 preference·최종 본인 직업 인증 필드가 필요하면 백엔드 계약을 추가해야 한다.
- 직군별 인정 증빙, 보관 기간, 처리 기간은 운영 정책으로 확정해야 한다. 확정되지 않은 완료 기한이나 즉시 삭제를 약속하지 않는다.

## 실기기 확인

1. iPhone/Android에서 가입 Step2 직군 선택 → 사진 선택 → 확대/추가/교체/삭제 → 프로필 저장·접수.
2. 사진 없이 가입 계속하기. 접수 실패 후 같은 사진 재시도 또는 가입 먼저 계속 → 성장 탭 재제출.
3. 5장 제한, HEIC 변환, 큰 사진, 권한 거절/설정 복귀, 선택 취소.
4. 관리자 승인/반려 후 본인 상태·반려 사유·추천/상세/내 미리보기의 서류 표시.
5. 네트워크 단절·접수 응답 유실·중복 클릭·계정 전환.
6. 알림을 누른 진입, 로그아웃/가입 중 보류, 앱 복귀 갱신.
7. 작은 화면·큰 글자·가로 화면에서 사진 및 긴 반려 사유를 읽고 하단 버튼에 접근할 수 있는지.

자동 검증: Jest 전체 116개 묶음·770개 테스트 통과. 변경한 파일의 TypeScript 오류 0개, 새 기능과 주요 연동 파일 ESLint 오류/경고 0개, git diff --check 통과. 저장소 전체 TypeScript에는 기존 SVG 및 오래된 화면 오류가 남아 있어 전체 타입 검사가 통과한 것은 아니다. 기존 테스트의 종료 핸들 문제 때문에 전체 Jest는 --forceExit로 실행했다.

실제 서버·S3·PASS·관리자 심사·푸시는 실기기/배포 환경에서 확인해야 한다. 백엔드·AI·인프라 소스는 수정하지 않았다.
