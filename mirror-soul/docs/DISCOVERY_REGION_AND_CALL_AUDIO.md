# 탐색 지역·통화 음량 개선

기반: `origin/dev`의 PR #199 병합 커밋 `5691f19`.
작업 브랜치: `codex/discovery-region-call-audio`.
RN 코드만 변경했으며 백엔드·AI·인프라 및 네이티브 설정·패키지는 변경하지 않았다.

## 탐색 지역

- 발견 바의 지역 이름 아래에 `1개 동`, `10개 동`, `30개 동`, `50개 동`을 표시한다. 개수는 기준 동네를 포함한 수이며 API의 `nearbyCount`와 같다.
- 시간과 지역 영역은 동일한 flex 비율을 사용한다. 지역 이름은 일반 크기에서 한 줄 말줄임, 개수는 별도 줄로 표시한다. 좁은 실제 부모 폭·큰 글자·긴 시간 표시에서는 두 행으로 전환한다. 전체 이름·범위는 접근성 레이블에 유지한다.
- 기존 슬라이더의 실제 View 높이는 4px이었다. 시각적인 선은 얇게 유지하면서 제스처 영역을 48px로 확대하고 각 단계에 최소 44px 높이의 버튼을 제공한다.
- 드래그는 수평 이동에만 활성화하며 세로 이동은 패널 스크롤을 허용한다. 같은 단계 내 이동마다 JS 콜백을 반복하지 않는다.
- 검색 영역, 지도, 선택 패널을 실제 레이아웃에서 분리한다. 지도 뒤에 패널이 덮이지 않으며 짧은 화면·큰 글자에서 패널 내용만 스크롤하고 확인 버튼은 바깥에 유지한다. 검색 키보드가 표시되면 패널을 숨겨 검색 결과에 공간을 배정한다.
- 지도에는 기준 동네 핀, 포함된 주변 동네 핀, 범위를 나타내는 원을 표시한다. 개수 변경 시 포함된 좌표에 맞춰 카메라를 조정한다. 기본 네이티브 핀을 사용해 50개 커스텀 View의 반복 스냅샷을 피한다.
- 현재 위치는 위치 권한이 있는 경우 Google 지도 기본 파란 점으로 표시한다. 화면 진입 시 권한을 읽기만 하며 위치 버튼을 눌러야 권한을 요청한다. GPS로 선택하면 실제 GPS 좌표와 동 중심이 함께 보이도록 맞춘다.
- 마커 콜아웃을 여는 탭은 기준 동네를 바꾸지 않는다. 지도 탭·핀 드래그·검색·현재 위치 선택은 기존 최근접 동 계산을 재사용한다.
- 현재 위치 대기는 15초로 제한하며 중복 요청·화면 종료 후 결과·GPS 대기 중 수동 선택·늦게 도착한 초기 권한 조회를 보호한다.
- 지역 저장은 동기 잠금으로 중복 실행을 막고, 실패하면 선택을 유지한다. 저장 응답 시 계정이 달라졌다면 캐시·안내·뒤로 이동을 적용하지 않는다.

### API

스냅샷을 먼저 확인한 후 최신 `HomeReqDTO`, `HomeResDTO`, `HomeService`의 해당 부분을 확인했다. 기존 `/home`, `/regions/coordinates`, `/regions/search`, `PUT /home/preferred-region`만 사용한다. `nearbyCount`는 1..50이며 기준 동네를 포함한다. 서버가 반환한 `includedRegionIds`와 설정을 캐시에 반영하고 추천 목록을 무효화한다. 원은 시각화이며 원 내부 모든 지역을 저장하는 방식이 아니다.

## 통화 음량

### 확인한 원인과 한계

- 소리 테스트는 expo-audio의 로컬 MP3 재생이며 실제 통화는 WebRTC 수신 트랙·InCallManager의 영상통화 오디오 세션을 사용한다. 동일한 음량 설정이라도 파일 음량과 출력 처리 차이로 체감 크기가 같다고 보장할 수 없다.
- 기존 RN의 수신 트랙 배율은 서버 값 0..100을 0..1로 변환했다. 서버 설정 100%가 원본 1배이므로 작은 원본을 키우는 기능은 없었다.
- 설치된 react-native-webrtc JS와 iOS/Android 네이티브 소스에서 `_setVolume` 지원을 확인했다. iOS는 수신 오디오 source volume, Android는 AudioTrack volume에 적용한다. 공식 문서의 범위는 0..10이다.
- 현재 RN은 연결 및 녹음 준비 후 InCallManager 영상통화 모드로 복구한다. 이어폰 우선 자동 출력·명시적 스피커 선택을 유지한다. 이번 변경은 출력 장치를 강제로 바꾸지 않는다.
- AI 코드에서 확인한 학습 샘플의 `_normalize_sample`은 파일 형식·샘플레이트·채널을 표준화하고 품질 지표로 검증한다. 이 함수 자체에는 loudness 정규화 필터가 없다. 실시간 출력 `QueuedAudioTrack.enqueue_encoded_audio`는 디코딩·리샘플링한 PCM을 전달하며 이 경로 자체에는 음량 보정이 없다. 다른 생성 모델 내부 동작까지 조사한 것은 아니다.
- 실제 사용자 녹음·생성 결과를 측정하지 않았으므로 가입 때 작은 목소리로 녹음한 것이 이번 현상의 원인이라고 단정할 수 없다.

### RN 변경

프로필 → 통화 소리 설정에 `작은 통화 음성 키우기`를 추가했다.

- 원래 크기(1배), 1.5배, 2배. 기본은 기존 1배.
- 서버 볼륨과 곱해 수신 통화 트랙에만 적용한다. 0% 음소거는 유지하고 마이크·녹음·서버 설정·프로필 미리듣기·소리 테스트에는 증폭을 적용하지 않는다.
- 이 기기의 SecureStore에 보관하는 로컬 설정이며 새 서버 필드는 없다. 기존 speechSpeed 미러 저장값도 유지한다.
- 스트림의 나중에 추가된 트랙과 설정 변경에 다시 적용한다. 특정 트랙 적용 실패가 다른 트랙을 막지 않는다.
- 과도한 증폭을 피하도록 최대 2배만 노출한다. 리미터나 자동 음량 정규화 기능이 아니므로 원본이 이미 크면 소리가 거칠어질 수 있다. 원래 크기로 되돌리는 안내를 제공한다.

### 엔지니어 협의

AI 측에서는 실제 생성 WAV와 송출 PCM의 RMS/peak 또는 LUFS를 측정하고, 학습 원본과 생성 출력의 음량 관계를 확인하는 것이 우선이다. 필요하면 생성 결과를 큐에 넣기 전에 음성 전체의 loudness 정규화와 true-peak 제한을 적용하되 문장 간 크기 차이·잡음 증폭·지연을 확인한다. 목표 수치는 실제 통화와 테스트 음성 비교 후 결정해야 한다. RN 2배 보정으로 원본 품질 문제나 출력 장치별 음량 차이를 모두 해결할 수는 없다.

참고: [react-native-webrtc 공식 트랙 볼륨 문서](https://github.com/react-native-webrtc/react-native-webrtc/blob/master/Documentation/BasicUsage.md), [Apple videoChat 모드](https://developer.apple.com/documentation/avfaudio/avaudiosession/mode-swift.struct/videochat).

## 검증 및 실기기 확인

- 전체 Jest 93개 묶음·581개 테스트 통과.
- 변경 코드 ESLint 통과, 변경 파일 TypeScript 오류 없음. 기존 전체 TypeScript 오류는 남아 있다.
- iOS·Android Metro/Hermes export 통과. 네이티브 설정을 변경하지 않아 prebuild·네이티브 재설치가 필요한 변경은 아니다.
- 실기기에서 지도 터치·현재 위치 정확도·마커 드래그·기기별 실제 음량은 직접 확인하지 않았다.

확인 순서:

1. 1/10/30/50개 선택 → 마커 수·표시 범위 → 저장 → 발견 바의 개수 → 재진입 값.
2. 단계 버튼·트랙 끝·드래그·세로 스크롤, 빠른 중복 저장, 실패 후 재시도.
3. 위치 허용/거부, GPS 지연 중 지도에서 직접 선택, 검색 중 키보드 닫기.
4. 작은 iPhone·Android·큰 글자·가로 화면에서 지도와 확인 버튼 접근.
5. iPhone 스피커에서 통화 중 기기 볼륨과 앱 상대 목소리 크기를 올리고 1배 → 1.5배 → 2배 비교. 소리가 거칠면 원래 크기로 복귀.
6. 이어폰·Bluetooth·연결 해제와 다음 통화에서 저장된 배율 유지, 상대 목소리 0% 음소거 확인.
