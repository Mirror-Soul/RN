## 디자인과 입력 흐름

기존 테마의 밝은 화면/어두운 화면 색상, 공통 폰트와 간격을 사용한다. 읽을 거리와 입력 영역을 나누고, 다음 버튼은 화면 하단에서 찾을 수 있도록 1~3단계의 공통 화면을 추가했다. 버튼 위에는 아직 필요한 입력을 안내하며, 저장 중에는 상태와 로딩 표시를 보여준다. 화면을 한 화면 높이에 억지로 압축하지 않고 필요한 스크롤을 허용한다. 키보드를 열면 큰 하단 버튼 영역을 접어 입력 공간을 확보한다. iOS는 ScrollView의 네이티브 키보드 inset 조정, Android는 기존 adjustResize를 사용하며 수동 화면 위치 측정과 KeyboardAvoidingView를 중복 적용하지 않는다. 계정 입력에는 iOS 키보드의 ‘입력 완료’ 도구와 Return 키의 닫기 동작을 제공한다.

- **계정 생성:** 이메일·비밀번호와 이용 전 확인을 카드로 구분한다. 이메일 인증 완료 뒤 주소를 변경할 수 있고, 주소 변경 시 이전 인증·타이머·인증 창을 초기화한다. 코드 발송 중 확인을 차단하고, 숫자 붙여넣기·시간 만료·재발송·지연된 인증 응답을 처리한다. 필수 약관과 별도 생체정보 동의를 유지하며, 마케팅 수신은 선택이다. 미지원 PASS를 필수처럼 설명하는 제목과 활성 버튼을 제거하고 실제 연령 확인 방식을 안내한다. 확인되지 않은 기기 내 암호화 안내도 이 세 화면에서 사용하지 않는다.
- **기본 프로필:** 닉네임과 지역, 하는 일을 읽기 쉬운 입력 카드로 묶는다. 닉네임은 중복 확인 완료 여부를 표시한다. 직업 상세 설명과 확인 서류는 선택으로 구분하고, 서류 설명은 펼쳐서 볼 수 있다. 파일 업로드와 실제 직업 검증 완료를 혼동하지 않도록 ‘서류 추가됨’이라고 표시하고 프로필 저장 시 함께 등록됨을 안내한다. 다른 직군을 고르면 이전 서류 연결을 제거하고, 같은 직군은 유지한다. 서류 업로드 중에는 직군 변경과 다음 단계 저장을 차단한다.
- **프로필 사진:** 기존 사진 선택·크롭·미리보기·별도 등록·변경·삭제 동작을 유지한다. 기본 정보 아래에 배치하며 사진 없이 계속할 수 있음을 제목과 하단 안내에서 설명한다.
- **이메일 입력 및 인증 후속 개선:** 로그인 정보 제목은 아이콘·강조색, 항목명은 차분한 색상, 안내는 회색, 입력값은 높은 대비로 구분한다. 이메일 인증 버튼을 누르면 먼저 기존 키보드를 닫는다. 인증창은 하단 시트로 구성하고 받는 이메일·시간·코드·확인 버튼을 나눈다. 자동 포커스로 안내를 가리지 않으며 숫자 6자리를 입력하거나 붙여넣으면 키보드를 닫되 자동 제출하지 않는다. 인증 시작·성공·닫기·재발송에서도 키보드를 정리하고, 실패하면 입력한 코드를 유지해 수정하거나 재시도할 수 있다. 시트의 확인 버튼은 스크롤 본문과 분리하고 iOS 키보드 회피는 시트의 전체 화면 기준으로 한 번만 적용한다.
- **성격 유형:** 처음에 유형을 임의로 선택하지 않는다. 네 성향을 일상적인 설명과 라디오 버튼으로 선택한다. 선택 개수와 현재 유형을 표시하며, 필요한 사용자만 ‘세부 조정’을 펼쳐 기존 슬라이더를 사용한다. 큰 글자에서는 선택 버튼이 한 열로 배치된다. 자기소개는 기존 160자 제한을 유지하고 예시·공개 여부·입력 길이를 안내한다.
- **상단 진행:** 현재 단계와 전체 단계 수, 다음 단계를 보여준다. 완료한 단계는 채우고 현재 단계는 테두리·점으로 표시한다. 마지막 화면에 도착해도 가입 완료로 표시하지 않는다. ‘가입 순서’에서 완료·진행 중·예정을 확인할 수 있으며, 단계 건너뛰기나 서버 상태와 다른 뒤로 이동 버튼을 추가하지 않는다.

## 저장과 접근성

API 요청 필드, 가입 상태 전환과 단계 순서는 유지한다. RN만 변경하고 백엔드·AI·인프라·submodule 포인터, 패키지 의존성과 네이티브 설정은 변경하지 않는다.

성향 버튼 선택은 기존 슬라이더 기준 왼쪽 25/오른쪽 75를 설정하며, 사용자는 세부 조정으로 바꿀 수 있다. 서버에는 기존과 같이 `100 - 슬라이더 값`을 보내므로 각 축 첫 글자 I/N/F/P의 선호도가 높은 값이다. 이는 사용자가 고른 성향이며 새 검사나 성격 판별 모델을 도입한 것이 아니다. 네 성향과 비어 있지 않은 자기소개가 있어야 계속할 수 있다.

계정 생성·성격 저장에는 동기 잠금으로 연타를 막는다. 비밀번호는 일치 여부와 오류를 안내하고, 입력 도중 불필요한 오류 표시를 줄인다. 고정 높이와 한 줄 말줄임을 줄이고 버튼·입력·문구가 큰 글자에 맞게 늘어나도록 한다. 라디오 선택 상태, 슬라이더 증감 동작, 진행 상태와 버튼의 로딩·비활성 상태를 접근성 속성으로 제공한다.

## 직업 확인 서류 안내와 선택 동의

Step2의 선택 항목을 펼치면 상대 프로필에 보이는 표시, 담당자의 수동 확인과 소요 시간, 파일 비공개 범위를 나누어 안내한다. 파일을 고르기 전에는 주민등록번호·주소·급여 등 확인에 불필요한 정보를 가리도록 안내한다. 예상 처리 일수나 완료 알림은 운영 기준과 기능이 확인되지 않아 약속하지 않는다. 서류 없이도 가입할 수 있는 기존 조건은 유지한다.

현재 동작과 향후 계획을 구분한다. 백엔드 `jobCertificationSubmitted`는 `jobCertificationObjectKey`가 있는지만 확인하며, 추천 카드와 상대 상세 프로필에는 **‘서류 제출’** 표시가 나온다. 사용자 요청의 수동 확인 방침을 안내에 반영했지만, 현재 서버의 관리자 확인 API는 실제 검토 처리를 하지 않고 승인 상태도 저장하지 않는다. 따라서 제출을 **‘직업 인증 완료’**로 표시하거나 검토 완료 마크를 약속하지 않는다. 향후 서버가 승인 결과를 제공하면 검토 중·인증 완료·보완 필요 상태를 구분하고, 승인된 경우에만 ‘직업 인증’ 마크를 표시하도록 연결해야 한다. 이번 작업에서는 백엔드 코드를 수정하지 않는다.

동의는 Step1의 가입 필수 약관에 추가하기보다 **Step2에서 서류를 올리기 직전에 별도의 선택 동의**로 받는 방향을 권장한다. 업로드를 시작하기 전에 동의 내용을 볼 수 있어야 하며, 동의하지 않아도 가입·둘러보기·트윈 통화에는 제한을 추가하지 않는다. 전체 가입 동의와 서류 이용 동의를 묶거나 미리 선택해 두지 않는다.

아래는 실제 동의 기능 추가 전에 확정할 항목이다. 현재 안내는 동의 수집을 대신하지 않는다.

- **목적:** 선택한 직업의 수동 확인과 승인 결과에 따른 공개 인증 표시. AI 성격·음성 학습용으로 사용한다는 문구를 넣지 않는다.
- **수집 항목:** 허용하는 증빙과 그 안에서 실제로 확인하는 최소 정보. 이름·소속·재직 여부 등을 모두 필요한 항목으로 단정하지 말고 운영 기준을 먼저 정한다.
- **보관 기간:** 검토 후 삭제할지, 일정 기간 보관할지 정책과 실제 파일 삭제 절차를 확정한다. 기존 개인정보 처리방침의 일반 보관 기간을 서류의 정책으로 임의 적용하지 않는다.
- **거부 안내:** 서류 확인을 신청하지 않을 수 있고, 그 경우 직업 인증 마크는 제공되지 않지만 기본 서비스 이용은 가능하다고 안내한다.
- **동의 기록:** 동의 문구 버전·동의 시각·이용자·해당 제출 건의 연결과 철회 절차. 현재 계정 생성 API의 `termsAgreed`는 별도의 서류 동의 기록을 저장하지 않는다. RN 체크박스만 추가해서 서버에 기록된 동의로 표현하지 않는다.

추천 흐름은 `서류 안내 → 선택 동의 확인 → 가린 서류 선택·촬영 → 업로드 → 프로필 저장 → 담당자 검토 → 승인 시 인증 표시`다. 이번 변경은 현재 API로 가능한 안내 개선까지만 적용하며, 선택 동의·검토 결과·인증 마크·검토 후 삭제는 정책 및 서버 연동이 필요한 후속 범위로 남긴다.

현재 파일은 프로필 저장 전에 S3에 업로드된다. 따라서 향후 동의는 프로필 저장 버튼이 아니라 **첫 업로드 전에** 확인해야 한다. 가입 중단이나 직군 변경으로 연결되지 않은 파일도 생길 수 있으므로, 보관·삭제 정책은 프로필에 연결된 서류뿐 아니라 미완료 업로드에도 적용할 수 있어야 한다. RN에서 파일 연결을 제거하는 것과 실제 저장 파일을 파기하는 것은 다르다.

동의를 근거로 개인정보를 수집한다면 목적·항목·보관 기간·거부 권리 및 불이익을 안내해야 한다. 선택 정보 동의 거부로 기본 서비스 이용을 제한하지 않는 방향도 [개인정보 보호법 제15조·제16조](https://law.go.kr/LSW/LsiJoLinkP.do?languageType=KO&lsNm=%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4+%EB%B3%B4%ED%98%B8%EB%B2%95&paras=1)를 참고했다.

## 검증

전체 Jest **34 suites / 200 tests 통과**. 새 테스트 24개는 단계 완료 표시·가입 순서·키보드 표시 시 순서 접기, 이메일 변경 시 인증 초기화, 선택 동의 조건, 코드 발송/만료/연타/지연 응답, 성향의 점수 방향·세부 조정, 성격 저장 실패 보존·중복 저장, 직군 변경 시 서류 유지/제거를 다룬다. 후속 테스트에는 코드 6자리 입력 후 키보드 닫기·자동 제출 방지, 인증창 닫기, 실패 후 코드 유지·재시도, 입력 중 하단 영역 접기와 키보드 종료 후 버튼 복원도 포함된다. 변경 파일 ESLint 오류·경고와 타입 오류는 0개이며, 전체 프로젝트 타입 검사에는 기존 오류가 남아 있다. iOS와 Android의 Metro/Hermes 번들 생성도 확인한다. 기존 Sentry 테스트 타이머에 의한 Jest 종료 경고는 남아 있다.

직업 서류 안내 후속 변경에서는 관련 기존 테스트 **3개 통과**, 변경 컴포넌트의 ESLint 오류·경고 및 타입 오류 0개를 확인했다. 전체 테스트 200개와 플랫폼 번들 검증은 앞선 키보드 개선 시점의 결과이며, 안내 문구 변경 후 다시 실행한 결과로 혼동하지 않는다. 안내 영역의 실기기 배치는 별도 확인이 필요하다.

실기기에서 실제 이메일 인증, 작은 화면·큰 글씨, 키보드와 하단 버튼, 지역/직군 드롭다운, 사진 편집 후 복귀, 세부 슬라이더를 움직인 후 다시 스크롤하는 동작을 확인해야 한다. 자동 테스트와 번들 생성만으로 시각적 배치·실제 키보드 동작을 확인했다고 보고하지 않는다.

기존 개발 앱에서 저장소 루트 기준:

```bash
cd mirror-soul

```
