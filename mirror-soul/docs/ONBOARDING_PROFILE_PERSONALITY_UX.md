## 디자인과 입력 흐름

기존 테마의 밝은 화면/어두운 화면 색상, 공통 폰트와 간격을 사용한다. 읽을 거리와 입력 영역을 나누고, 다음 버튼은 화면 하단에서 찾을 수 있도록 1~3단계의 공통 화면을 추가했다. 버튼 위에는 아직 필요한 입력을 안내하며, 저장 중에는 상태와 로딩 표시를 보여준다. 화면을 한 화면 높이에 억지로 압축하지 않고 필요한 스크롤을 허용한다. 입력 중 키보드를 피하고, 실제 화면 위치를 측정해 상단 진행 영역·safe area·라우트 래퍼의 위치를 반영한다.

- **계정 생성:** 이메일·비밀번호와 이용 전 확인을 카드로 구분한다. 이메일 인증 완료 뒤 주소를 변경할 수 있고, 주소 변경 시 이전 인증·타이머·인증 창을 초기화한다. 코드 발송 중 확인을 차단하고, 숫자 붙여넣기·시간 만료·재발송·지연된 인증 응답을 처리한다. 필수 약관과 별도 생체정보 동의를 유지하며, 마케팅 수신은 선택이다. 미지원 PASS를 필수처럼 설명하는 제목과 활성 버튼을 제거하고 실제 연령 확인 방식을 안내한다. 확인되지 않은 기기 내 암호화 안내도 이 세 화면에서 사용하지 않는다.
- **기본 프로필:** 닉네임과 지역, 하는 일을 읽기 쉬운 입력 카드로 묶는다. 닉네임은 중복 확인 완료 여부를 표시한다. 직업 상세 설명과 확인 서류는 선택으로 구분하고, 서류 설명은 펼쳐서 볼 수 있다. 파일 업로드와 실제 직업 검증 완료를 혼동하지 않도록 ‘서류 추가됨’이라고 표시하고 프로필 저장 시 함께 등록됨을 안내한다. 다른 직군을 고르면 이전 서류 연결을 제거하고, 같은 직군은 유지한다. 서류 업로드 중에는 직군 변경과 다음 단계 저장을 차단한다.
- **프로필 사진:** 기존 사진 선택·크롭·미리보기·별도 등록·변경·삭제 동작을 유지한다. 기본 정보 아래에 배치하며 사진 없이 계속할 수 있음을 제목과 하단 안내에서 설명한다.
- **성격 유형:** 처음에 유형을 임의로 선택하지 않는다. 네 성향을 일상적인 설명과 라디오 버튼으로 선택한다. 선택 개수와 현재 유형을 표시하며, 필요한 사용자만 ‘세부 조정’을 펼쳐 기존 슬라이더를 사용한다. 큰 글자에서는 선택 버튼이 한 열로 배치된다. 자기소개는 기존 160자 제한을 유지하고 예시·공개 여부·입력 길이를 안내한다.
- **상단 진행:** 현재 단계와 전체 단계 수, 다음 단계를 보여준다. 완료한 단계는 채우고 현재 단계는 테두리·점으로 표시한다. 마지막 화면에 도착해도 가입 완료로 표시하지 않는다. ‘가입 순서’에서 완료·진행 중·예정을 확인할 수 있으며, 단계 건너뛰기나 서버 상태와 다른 뒤로 이동 버튼을 추가하지 않는다.

## 저장과 접근성

API 요청 필드, 가입 상태 전환과 단계 순서는 유지한다. RN만 변경하고 백엔드·AI·인프라·submodule 포인터, 패키지 의존성과 네이티브 설정은 변경하지 않는다.

성향 버튼 선택은 기존 슬라이더 기준 왼쪽 25/오른쪽 75를 설정하며, 사용자는 세부 조정으로 바꿀 수 있다. 서버에는 기존과 같이 `100 - 슬라이더 값`을 보내므로 각 축 첫 글자 I/N/F/P의 선호도가 높은 값이다. 이는 사용자가 고른 성향이며 새 검사나 성격 판별 모델을 도입한 것이 아니다. 네 성향과 비어 있지 않은 자기소개가 있어야 계속할 수 있다.

계정 생성·성격 저장에는 동기 잠금으로 연타를 막는다. 비밀번호는 일치 여부와 오류를 안내하고, 입력 도중 불필요한 오류 표시를 줄인다. 고정 높이와 한 줄 말줄임을 줄이고 버튼·입력·문구가 큰 글자에 맞게 늘어나도록 한다. 라디오 선택 상태, 슬라이더 증감 동작, 진행 상태와 버튼의 로딩·비활성 상태를 접근성 속성으로 제공한다.

## 검증

전체 Jest **33 suites / 195 tests 통과**. 새 테스트 19개는 단계 완료 표시·가입 순서·키보드 표시 시 순서 접기, 이메일 변경 시 인증 초기화, 선택 동의 조건, 코드 발송/만료/연타/지연 응답, 성향의 점수 방향·세부 조정, 성격 저장 실패 보존·중복 저장, 직군 변경 시 서류 유지/제거를 다룬다. 변경 파일 ESLint 오류·경고와 타입 오류는 0개이며, 전체 프로젝트 타입 검사에는 기존 오류가 남아 있다. iOS와 Android의 Metro/Hermes 번들 생성도 확인한다. 기존 Sentry 테스트 타이머에 의한 Jest 종료 경고는 남아 있다.

실기기에서 실제 이메일 인증, 작은 화면·큰 글씨, 키보드와 하단 버튼, 지역/직군 드롭다운, 사진 편집 후 복귀, 세부 슬라이더를 움직인 후 다시 스크롤하는 동작을 확인해야 한다. 자동 테스트와 번들 생성만으로 시각적 배치·실제 키보드 동작을 확인했다고 보고하지 않는다.

기존 개발 앱에서 저장소 루트 기준:

```bash
cd mirror-soul
npx expo start --dev-client
```

이번 변경 때문에 prebuild나 Pods 재설치는 필요하지 않다.
