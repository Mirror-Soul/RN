# 로그인·회원가입 진입 및 가입 재개 UX

브랜치: `codex/auth-entry-onboarding-ux`

출발점: 원격 `dev`의 `0b92e23` (발견·매칭 PR #197 병합). RN만 수정하며 백엔드·AI·인프라 및 submodule 포인터는 변경하지 않는다.

## 사용자 결정과 설계

- 로그인은 가장 중요한 행동이다. 첫 화면에 폼과 주요 버튼을 바로 제공하고, 회원가입은 보조 버튼으로 연결한다. 입력하려면 탭을 먼저 바꿔야 하는 구조를 제거했다.
- 가입했다가 중단한 사실을 기억하지 못할 수도 있다. 별도의 ‘가입 재개’ 메뉴를 찾아야 한다고 가정하지 않고, 로그인과 회원가입 중 기존 이메일 확인 두 경로에서 자연스럽게 재개한다.
- 기존 공통 서체·테마 색상·시안/퍼플 그라디언트를 사용한다. 반복 설명, 큰 장식, 고정 높이의 마스킹 텍스트를 덜어냈다. 서비스가 완벽한 상대를 보장한다거나 데이터를 기기 안에서만 암호화한다는 검증되지 않은 표현을 표시하지 않는다.

## 실제 백엔드 계약

API 스냅샷 `.claude/artifacts/backend-schema.json`과 `analysis-report.md`를 먼저 확인하고, 백엔드 `cded928`의 AuthService·JoinService·EmailAuthService·OnboardingService·InterviewService·VisualService와 DTO를 확인했다. 소스는 읽기만 했다.

| 로그인 응답 상태 | 서버에 완료된 단계 | RN의 다음 화면 |
| --- | --- | --- |
| `ONBOARD_A` | 계정 생성 | 기본 프로필 |
| `ONBOARD_B` | 기본 프로필 | 성격 유형 |
| `ONBOARD_C` | 성격 유형 | 음성 인터뷰 |
| `ONBOARD_D` | 음성 인터뷰 | 나의 아바타 만들기 |
| `ACTIVE` | 전체 가입 완료 | 메인 탭 |

- `POST /auth/login`은 가입 미완료 회원도 인증하며 실제 `userStatus`와 토큰을 반환한다. 신규 계정 생성은 `ONBOARD_A`와 토큰을 반환한다.
- `POST /join/send-code`는 이미 등록된 이메일에 `DUPLICATE_EMAIL`을 반환한다. 최종 계정 생성에서도 중복 확인이 있으므로 두 위치 모두 로그인 연결을 제공한다.
- 이메일만으로 가입 완료 여부·단계를 알아낼 수 있는 응답은 없다. 기존 이메일이라는 사실만 안내하고 단계는 로그인 성공 후에만 표시한다.
- 프로필·성격은 각각 단계별 제출 성공 시 다음 상태가 된다. 아직 제출하지 않은 폼 입력은 서버에서 자동 복원되지 않는다.
- 음성 인터뷰는 질문별 저장이 가능하고 같은 질문 답변은 덮어쓴다. 전체 답변이 저장되면 `ONBOARD_D`가 된다. 하지만 현재 질문 조회는 질문 목록만 반환하며, 본인의 저장 답변·다음 미응답 질문을 조회하는 API는 없다.
- 얼굴 영상 저장 후 서버는 `ACTIVE`로 전환한다. 처리 작업이 진행 중이라고 가입 상태를 임의로 바꾸지 않는다.
- 토큰 갱신 응답은 새 access token만 제공하고 현재 가입 단계는 제공하지 않는다. 앱의 기존 정책대로 미완료 세션은 재실행 시 로그인으로 현재 서버 상태를 다시 확인한다. 마지막 로컬 단계만 믿고 자동 복원하지 않는다.

## 구현 흐름

1. 첫 화면에서 즉시 로그인하거나 회원가입으로 이동한다. 이동할 때 입력한 이메일은 유지하며 비밀번호는 전달·저장하지 않는다.
2. 기존 이메일로 회원가입을 다시 시도하면 ‘이 이메일로 만든 계정이 있어요’와 ‘로그인하고 계속’을 표시한다. 다른 이메일로 바꾸면 이전 안내를 지운다.
3. 최종 가입 요청에서 중복이 확인되어도 하단 고정 버튼을 로그인 행동으로 전환해 위로 다시 스크롤할 필요가 없다.
4. 로그인 성공 후 미완료 회원에게 현재 저장된 단계·다음 단계와 ‘이어서 가입하기’를 안내한다. 완료 회원은 메인으로 이동한다.
5. 새 계정 생성 직후에는 재개 안내를 거치지 않고 기본 프로필로 바로 이동한다. 재개 안내는 메모리 상태로만 관리하며 각 단계 저장이나 로그아웃 시 해제한다.
6. ‘나중에 이어하기’는 공통 `performLogout()`으로 세션·캐시를 정리하고 로그인으로 돌아간다. 서버에 저장한 가입 정보는 삭제하지 않는다.
7. 앱 재실행 시 미완료 로컬 세션이 있었다면 익명 안내만 유지하고 로그인으로 상태를 확인한다. 이 안내에 이메일·토큰·단계를 보관하지 않는다.
8. 비밀번호 찾기는 기존 API를 사용한다. 입력한 이메일을 유지하고 재설정 후에도 새 비밀번호로 직접 로그인해 현재 가입 상태를 확인한다.

## 정확히 안내하는 복원 범위

완료한 단계는 유지하지만 미저장 입력·녹음·촬영을 모두 복원한다고 약속하지 않는다. 음성 인터뷰 재개는 현재 API로 첫 질문부터 진행하며 안내 화면에서 이를 알린다. 이미 저장한 질문을 다시 저장하면 새 답변으로 교체된다.

이메일 자체를 기억하지 못한 경우 RN이 계정 소유권이나 이메일을 자동으로 알아낼 수는 없다. 지원 절차나 본인 확인을 통한 계정 찾기 계약이 필요하며 존재하지 않는 ‘이메일 찾기’ 버튼은 추가하지 않았다.

## 백엔드 확장 권장 사항

| 필요 상황 | 권장 계약 |
| --- | --- |
| 로그인 없이도 저장된 세션으로 정확한 단계 복구 | 인증된 `GET /onboarding/progress`: `userStatus`, `nextStep`, 완료 단계, 갱신 시점. 로컬 상태보다 서버 값을 우선하고 현재 단계의 허용 행동도 확인 |
| 음성 인터뷰를 마지막 질문부터 재개 | 사용자별 저장 답변/질문 ID와 `nextUnansweredQuestionId`를 제공. 전체 완료와 질문 추가·삭제도 일관되게 처리 |
| 미저장 폼까지 보존 | 명시적인 임시 저장 API와 만료 정책. 완료 단계 저장과 초안 저장을 구분 |
| 이메일 자체를 잊은 계정 찾기 | 소유권 확인을 포함한 지원 절차/본인 인증 계약. 인증 전 개인 정보나 가입 단계를 노출하지 않음 |

기존 API만으로 ‘계정 생성 이후 중단 → 같은 이메일로 로그인 → 저장한 단계 이후 재개’는 가능하다. 위 확장은 더 세밀한 재개에 필요한 사항이며 이번 UI를 사용하는 데 새 API가 필수인 것은 아니다.

## 반응형·접근성 및 확인 항목

안전 영역·공통 콘텐츠 폭·24pt 좌우 여백을 사용한다. 작은 화면에서는 제목 크기를 줄이고 키보드가 나타나면 소개 문구를 접되 입력 상태는 유지한다. 입력창·버튼·오류 안내는 내용과 글자 크기에 맞춰 늘어나며 고정 높이로 자르지 않는다. 비밀번호 표시와 보조 행동은 최소 48pt 영역을 제공한다.

### iOS·Android 차이 보완

- 로그인: iOS는 `automaticallyAdjustKeyboardInsets`로 스크롤 영역을 조정하고, Android는 기존 네이티브 `adjustResize`를 그대로 사용한다. Android에 `KeyboardAvoidingView` 높이 조정을 함께 적용하지 않는다. 키보드 네이티브 설정·프로젝트·라이브러리는 변경하지 않았다.
- iOS는 키보드가 나타나기 전 `keyboardWillShow/Hide`, Android는 `keyboardDidShow/Hide`로 소개 영역을 접고 펼친다. iOS에서는 드래그로 키보드를 자연스럽게 내리고, Android는 기본 뒤로가기와 스크롤 닫기 동작을 유지한다.
- Android 10 이하에서 `adjustResize`와 키보드 이벤트의 조합이 제한될 수 있으므로, 로그인 화면은 실측 스크롤 영역이 짧아졌을 때도 소개를 접는다. 큰 글자 설정에서도 장식을 줄이고 폼·버튼은 계속 확장·스크롤할 수 있게 한다. 소개가 접히거나 창 크기가 바뀌어도 이메일·비밀번호를 초기화하지 않는다.
- 비밀번호 찾기: 로그인과 동일한 네이티브 키보드 대응을 적용하고 첫 터치로 확인 버튼을 사용할 수 있게 한다. 인증 코드 붙여넣기에서 숫자만 받아 6자리 입력 후 키보드를 닫되 자동 제출하지 않는다. 요청 중에는 입력을 잠그고, 새 비밀번호의 ‘다음’은 확인 입력창으로 초점을 넘긴다.
- 비밀번호 찾기의 헤더가 상단 안전 영역을 담당하고 외부 컨테이너는 좌우·하단을 담당해 inset을 두 번 더하지 않는다. 하단 제스처·내비게이션 영역은 안전 영역으로 확보한다. 인증 코드·버튼은 고정 높이를 제거하고 최소 높이로 처리한다. 복구 화면을 직접 열었을 때 뒤로가기의 목적지는 로그인이다.
- 가입 재개: Android 뒤로가기도 ‘나중에 이어하기’와 같은 로그아웃·세션 정리를 사용하며 중복 요청을 막고 화면을 떠나면 리스너를 제거한다. 유효한 미완료 세션에서만 뒤로가기 리스너를 등록한다.
- 이메일 인증 모달: 기존 중앙 모달을 유지한다. 설치된 RN Android 모달도 `SOFT_INPUT_ADJUST_RESIZE`를 사용하므로 추가 높이 보정을 적용하지 않는다. 기존 6자리 입력·닫기 시 키보드 정리와 내부 스크롤은 유지한다.

근거: 설치된 RN 0.81.5 소스·생성된 AndroidManifest를 읽기만 했으며 [RN ScrollView 문서](https://reactnative.dev/docs/scrollview#automaticallyadjustkeyboardinsets)와 [Keyboard 문서](https://reactnative.dev/docs/keyboard#addlistener)에서 플랫폼 지원 범위를 확인했다. 자동 테스트의 화면 크기·글자 크기 변경은 상태 보존과 동작 검증이며 실제 픽셀 배치 검증을 대신하지 않는다.

| 실기기 확인 조합 | 확인할 동작 |
| --- | --- |
| 작은 iPhone / 320~360dp Android | 두 입력창, 로그인·가입 버튼에 스크롤로 접근, 키보드 종료 후 입력 유지 |
| 홈 인디케이터 iPhone / Android 제스처·3버튼 내비게이션 | 하단 버튼이 시스템 영역에 가리지 않는지 |
| 기본·큰 글자 / 라이트·다크 | 글자 잘림·겹침, 긴 오류·이메일 줄바꿈, 버튼 높이 확장 |
| 태블릿·폴더블·분할 화면 | 안전 영역 안의 공통 콘텐츠 폭과 크기 변경 시 입력 유지 |
| iOS 숫자 키보드 / Android Gboard·삼성 키보드 | 6자리 입력·붙여넣기 후 닫기, 첫 터치로 인증, 비밀번호 ‘다음’·‘완료’ |
| Android 뒤로가기 | 키보드 닫기, 인증 모달 닫기, 재개 화면에서 중복 없이 나중에 진행 |

실기기에서는 작은 iPhone·Android, 큰 글자, 가로 화면, 라이트·다크 모드에서 입력 초점과 키보드 가림·버튼 접근성을 확인해야 한다. 신규 가입, `ONBOARD_A`~`D` 재로그인, `ACTIVE` 로그인, 기존 이메일 재가입, 비밀번호 재설정, 서버 지연 시 입력 유지·재시도를 각각 확인한다. 실제 인증 계정을 이용한 서버 검증과 기기별 육안 확인은 자동 테스트로 대체할 수 없다.

## 자동 검증

후속 로고 작업에서는 로그인 화면을 로고 중심의 간결한 구성으로 바꾸고 `app.config.js`의 아이콘·시작 화면 이미지 경로를 업데이트했다. 키보드·가입 재개 동작은 유지한다. 로고 자산·프롬프트·앱 아이콘 재빌드 방법은 [MIRRORSOUL_BRAND.md](./MIRRORSOUL_BRAND.md)에 정리했다.

- 전체 Jest: 75개 테스트 묶음, 425개 테스트 통과. 기존 비동기 핸들 때문에 `--forceExit` 옵션을 사용했다.
- 로그인 중복 제출·실패 후 재시도, 이메일 전달·비밀번호 비전달, 키보드 표시 중 입력 유지, 중복 이메일 로그인 연결, 각 서버 상태의 라우팅·재개·나중에 진행을 검증했다.
- 키보드 iOS·Android 이벤트, 이벤트 없이 Android 화면이 줄어든 경우, 작은 창·큰 글자·태블릿 크기 변경 중 입력 유지, Android 재개 화면 뒤로가기·리스너 정리, 복구 코드 붙여넣기·숫자 키보드 닫기·요청 중 입력 잠금을 추가 검증했다.
- 수정·추가한 TypeScript 파일 28개의 ESLint 통과.
- iOS·Android JavaScript/Hermes 번들 export 통과. 네이티브 빌드나 실기기 실행을 검증한 결과는 아니다.
- 프로젝트 전체 TypeScript 검사에는 기존 오류가 남아 있다. 수정·추가 파일에서는 TypeScript 오류가 발견되지 않았다.
