# 프로필 API 연동 및 서버 요청 정리

## 범위와 현재 구현

- RN 브랜치: `codex/profile-api-reliability`, PR #195가 머지된 `origin/main` (`0311004`)에서 시작.
- 백엔드·AI·인프라 소스는 수정하지 않았다. 직업 인증 운영 화면도 구현하지 않았다.
- 기존 API 스냅샷은 `.claude/artifacts`에서 먼저 확인했다. 이후 변경된 프로필·학습 관련 서비스는 실제 소스와 원격 main으로 재확인했다.
- 이전 분석에서 확인한 백엔드 main: `81892759bc6b0dd2a4cb3df32938b02fcf42aeef`, AI main: `0bac9e460bc72314b76c16f980c689f04cbce577`.
- 아래 계약 확장은 **엔지니어에게 요청할 제안**이며, 현재 배포 API에 존재한다고 가정하지 않는다. 실사용 계정 응답·S3 HTTP 상태·배포 워커 설정은 별도 확인 필요.

RN에서 이번에 보완한 내용:

1. 상단 프로필 사진과 공개 미리보기에서 등록 직후 로컬 사본을 사용한다. 서버 다운로드 실패를 등록 실패와 구분하며 최신 URL 조회·이미지 재시도를 제공한다. 로컬 사본은 세션 캐시이므로 서버의 이미지 접근 문제를 대신 해결하지 못한다.
2. 본인 미리듣기 새로고침은 `GET /my-page/profile`을 사용한다. 상대 조회 API에 `null` UUID를 보내지 않는다.
3. 프로필 기본·상세·트윈 조회 캐시는 사용자 UUID로 분리하고, 이전 조회는 AbortSignal을 통해 취소한다. 닉네임·사진 변경과 음성 업데이트 제출 후 관련 캐시를 갱신한다.
4. 프로필·트윈 화면 진입과 앱 복귀 시 재조회한다. 미리듣기가 없을 때는 화면이 활성화된 동안만 15초 간격, 최대 90초간 확인한다. 이후 수동 조회를 제공한다. 이것은 작업 상태 판별이나 완료 보장이 아니다.
5. 본인/상대 미리듣기 플레이어를 공통화했다. 로딩·15초 대기 초과·재생 실패·재시도·끝난 음성 다시 듣기·화면 이탈/백그라운드 정지를 처리한다. URL이 같아도 수동 재시도는 플레이어를 새로 만든다.
6. 가입 MBTI를 AI 분석 점수처럼 표시하지 않는다. 음성 업데이트 횟수·날짜는 제출 이력으로 표시한다. 미리듣기 `null`을 무조건 학습 중으로 해석하지 않는다.
7. 계정·오디오·알림 조회도 사용자별 캐시·취소·화면 복귀 재조회로 통일한다. 조회 실패 시 재시도하고, 저장 실패 시 마지막 서버 확인 값을 유지한다. 빠른 연속 저장과 이전 계정의 늦은 응답을 차단한다.
8. 재생 속도 UI를 `통화 소리 설정`으로 바꿨다. 기존 볼륨 API를 실제 WebRTC 수신 음성과 본인/상대 미리듣기에 연결하고, 로컬 안내 음성·마이크 권한 확인을 제공한다. 마이크 입력 음량과 기기의 전체 볼륨은 바꾸지 않는다.
9. 알림 설정을 대화·통화·시간 안내로 나누고, 기존 채팅 API로 대화방별 메시지 알림 관리를 추가했다. OS 표준 스위치와 상태 문구를 사용하고 기기 권한 확인·설정 복귀 시 Android 기기 등록 복구를 제공한다. 추가 서버 계약은 [알림 API 요청 문서](./NOTIFICATION_API_HANDOFF.md)에 정리했다.
10. 계정 관리에 기존 API의 로그인 이메일과 공개 미리보기·도움말 연결을 추가했다. 닉네임 편집·로그아웃·탈퇴 확인창을 키보드/큰 글자에 맞게 정리하고 실패·계정 변경을 처리했다. 계정 보안과 탈퇴 정책 요청은 [계정 API 요청 문서](./ACCOUNT_API_HANDOFF.md)에 정리했다.

## 현재 조회 연결

| 영역 | API | 현재 의미 / 한계 |
|---|---|---|
| 프로필 상단 | `GET /my-page` | 이름·이메일·profileImageUrl |
| 내 공개 미리보기 | `GET /my-page/profile` | 공개 필드를 선별해서 상대 프로필 레이아웃에 전달. 계정 이메일·설정은 전달하지 않음 |
| 트윈 상태 | `GET /my-page/profile`, `GET /evolve` | 성향 태그·MBTI·미리듣기와 싱크로율·음성 제출 이력 |
| 사진 변경/삭제 | `PATCH/DELETE /my-page/profile-image` | 업로드 객체를 프로필에 연결/해제 |
| 음성 업데이트 | `POST /evolve/voice` | 작업 접수 결과 `jobId`, `status`. HTTP 성공은 학습 완료가 아님 |
| 잔여 시간·충전 | `GET/POST /my-page/buy-time` | 연결됨 |
| 계정·닉네임·탈퇴 | `/my-page/account`, `DELETE /my-page` | 연결됨. 조회 실패 복구·계정별 캐시 보완. 로그아웃도 기존 API 유지 |
| 음성/오디오 설정 | `GET/PATCH /my-page/audio-settings` | 볼륨 조회·저장·실제 통화/미리듣기 적용. 화면에서 속도 설정은 제거하고 PATCH의 기존 속도 값은 보존 |
| 알림 설정 | `GET/PATCH /my-page/alarm`, `GET /chat/rooms`, `GET/PATCH /chat/rooms/{room-id}/notification` | 시간 부족·부재중 통화와 대화방별 메시지 알림 연결. 메시지 발송의 방별 선호도 필터 확인; 나머지 실제 발송은 별도 검수 필요 |
| 혜택·이벤트 알림 | 대응 서버 API 없음 | 서버와 연결되지 않은 토글을 화면에서 제거. 제공하려면 발송 정책·저장 계약부터 추가 |
| 테마·FAQ·약관·문의 | 로컬 설정/정적 콘텐츠/외부 링크 | 해당 특성에 맞게 유지 |

## 요청 1: 이미지 다운로드 계약 통일 — 백엔드 우선

현재 `FileService.buildFileUrl()`은 서명 없는 S3 주소를 저장하고 본인/상대 조회는 이를 반환한다. 저장소의 S3 공개 차단 정책이 배포와 같다면 해당 URL은 일반 이미지 다운로드에 사용할 수 없다. 등록 성공, DB 필드 존재, 실제 이미지 GET 성공을 각각 확인해야 한다.

권장 MVP:

- DB에는 영구 식별자인 objectKey를 정본으로 유지하고, 조회 시 다운로드 URL을 발급한다. 서명 URL을 영구 DB 값으로 저장하지 않는다.
- 공통 미디어 응답 생성기를 본인 기본/상세, 추천 목록/상세, 이력 등 사진을 반환하는 모든 경로에서 재사용한다.
- 기존 `profileImageUrl`은 유지하여 RN 호환성을 보장하고, `profileImageId`와 `profileImageUrlExpiresAt`을 추가한다. 삭제 시 세 필드 모두 null.
- 사진 변경 응답도 동일한 식별자·URL·만료 시간을 반환한다. RN은 파일 ID로 사진 변경을 판단하고 만료 시간으로 URL을 갱신한다.
- 공개 CDN을 이미 운영한다면 안정적인 CDN URL을 제공하는 대안도 가능하다. MVP 때문에 버킷 전체를 공개할 필요는 없다.
- 인증 서류는 프로필 사진과 다른 접근 정책을 사용한다. 일반 프로필 응답에 서류 URL/objectKey를 포함하지 않는다.

검수: 신규 등록 → 앱 종료/다른 기기 로그인 → 본인/상대 조회 → 만료 후 재조회 → 교체 → 삭제에서 모두 같은 사진 상태여야 한다. URL 자체는 달라도 파일 ID는 동일해야 한다.

## 요청 2: 실제 음성 미리듣기 생성 — AI + 백엔드

현재 확인한 최신 AI 워커의 완료 결과는 `elevenlabsVoiceId`, `voiceScore`만 포함한다. `model_calling/README.md`도 `introAudio`를 현재 생략한다고 명시한다. 백엔드는 활성 AiVoiceProfile의 introAudio 정보가 없으면 `voicePreview: null`을 반환한다. 따라서 폴링만으로 해결되지 않는다.

권장 처리:

1. AI에서 학습된 voiceId로 짧은 고정 소개 문장을 TTS 생성한다. 사용자 제출 녹음을 트윈 음성인 것처럼 재생하지 않는다.
2. 생성 파일은 기존 계약에 맞게 `voice-intros/{userUuid}/{jobId}.mp3` 등에 업로드한다. `audio/mpeg`, 5 MiB 이하, 30초 이하를 지킨다.
3. 완료 이벤트에 기존 `introAudio`의 `bucket`, `objectKey`, `contentType`, `sizeBytes`, `durationMs`를 포함한다. 모델 voiceId 생성과 소개 파일 생성 결과를 같은 jobId로 연결한다.
4. SQS 재전달/게시 재시도 시 같은 작업의 voiceId·완료 결과를 재사용한다. 미리듣기 실패 때문에 음성 클론을 다시 만들어 비용을 중복 지불하지 않도록 단계별 결과를 보관한다.
5. 미리듣기 생성이 실패해도 통화 가능한 모델을 사용할 수 있게 하려면 `introAudioStatus: READY | FAILED`와 오류를 명시하는 계약을 추가한다. RN에는 학습 완료와 미리듣기 생성 실패를 따로 전달한다. 실패를 무기한 PROCESSING으로 남기지 않는다.
6. 백엔드는 소유자·jobId·객체 경로를 검증하고 결과를 멱등 처리한다. 최신 작업보다 늦게 도착한 오래된 결과가 활성 모델을 되돌리지 않도록 현재 보호 로직을 유지한다.
7. 새 모델에 미리듣기가 없다고 기존 정상 샘플이 갑자기 사라지지 않도록 정책을 정한다. 이전 샘플 유지 시 모델 버전·작업 ID를 함께 반환해 RN이 이전 목소리라고 안내할 수 있게 한다.

RN에 내려오는 `voicePreview`의 기존 필드는 유지하고 `id` 또는 `jobId`, `urlExpiresAt`을 추가해 URL 재발급과 실제 샘플 교체를 구분한다.

## 요청 3: 학습 작업과 재생 가능 상태를 분리한 조회 — 백엔드

현재 상태는 서로 다른 대상이다:

- 학습 작업: `PENDING / PROCESSING / COMPLETED / FAILED`
- 음성 프로필: 활성 `ACTIVE`
- 전체 트윈: `PENDING / READY` (얼굴·음성·성격 준비 조건)
- 미리듣기: 파일이 있는 경우에만 재생 URL 제공

`syncRate == null`, 제출 횟수, `voicePreview == null`만으로 작업 상태를 추론해서는 안 된다.

권장 MVP는 기존 `GET /my-page/profile`에 공개 내용과 별도로 **본인 전용 상태 필드**를 추가하는 것이다. 자체 추천 조회와 상태 조회를 여러 번 조합하기보다 백엔드에서 일관된 스냅샷을 반환한다. `GET /evolve`는 동일한 상태 서비스/집계 규칙을 재사용한다.

제안 예시 (기존 필드는 유지):

```json
{
  "voicePreview": null,
  "voicePreviewStatus": "PROCESSING",
  "twinState": {
    "status": "PENDING",
    "updatedAt": "2026-10-04T00:00:00Z",
    "revision": 12,
    "voice": {
      "activeJobId": 100,
      "latestJob": {
        "jobId": 101,
        "status": "PROCESSING",
        "previewStatus": "PROCESSING",
        "submittedAt": "2026-10-04T00:00:00Z",
        "completedAt": null,
        "errorCode": null
      }
    },
    "face": { "status": "COMPLETED" },
    "personality": { "status": "PROCESSING" }
  },
  "refreshAfterMs": 15000
}
```

- 컴포넌트별 API 상태는 `NOT_STARTED / PENDING / PROCESSING / COMPLETED / FAILED`로 통일하고, 내부의 얼굴 READY/음성 ACTIVE는 백엔드에서 변환한다.
- 전체 트윈의 기존 PENDING/READY 의미는 유지한다. 작업 실패는 컴포넌트에서 나타내고, 새 업데이트가 실패해도 이전 활성 트윈의 사용 가능 여부는 별도로 보존한다.
- `voicePreviewStatus`는 `NOT_AVAILABLE / PROCESSING / READY / FAILED`. READY일 때만 유효한 voicePreview를 함께 준다. 이 필드는 실제 반환하는 샘플의 상태를 나타낸다. 직전 샘플을 유지하면 READY이며, 새 작업의 미리듣기 생성 상태는 latestJob.previewStatus에 따로 표시한다. 활성/최신 작업 ID로 버전을 구분한다.
- 본인 전용 실패 코드·작업 이력은 상대 공개 응답에 노출하지 않는다. RN에는 사용자 안내에 필요한 오류 코드만 전달하고 내부 예외 원문은 제외한다.
- `refreshAfterMs`는 갱신할 작업이 있을 때만 제공, 모두 종료되면 null. 앱이 화면을 떠나거나 백그라운드가 되면 폴링을 중단한다. 처음부터 웹소켓을 추가할 필요는 없다.
- 제출 횟수는 `voiceSubmissionCount`, 완료 횟수는 `voiceCompletedCount`, 제출/완료 시각도 각각 명명한다. 기존 필드의 뜻을 조용히 바꾸지 않는다.
- URL만 새로 발급되는 응답에서도 파일 ID/revision은 바뀌지 않게 한다. 재생 중 무관한 상태 갱신으로 플레이어가 교체되지 않도록 한다.

검수: 접수·처리·성공·재시도 가능한 실패·최종 실패·오래된 작업의 지연 완료·앱 재실행·새 작업 실패 시 이전 트윈 유지.

## 직업 인증 운영 화면 — 검토만, 구현하지 않음

현재 자료는 User의 `jobCertificationObjectKey`에 연결된다. 프로필의 `jobCertificationSubmitted`는 자료 제출 여부일 뿐 승인 여부가 아니다. `/admin/job-verify`도 현재 자료 조회·승인·반려 서비스 없이 성공 응답만 반환하는 빈 구현이다.

**작은 웹 운영 화면을 권장한다.** S3 탐색은 심사 대상자·제출 직업·처리 상태·이력을 한 번에 연결하기 어렵다. 화면만 만들기보다 심사 상태와 관리자 API를 먼저 정해야 한다.

MVP 운영 흐름:

1. 대기 목록: 제출 순서, 대기 기간, 사용자 식별자, 신청 직업, 현재 상태. 페이지네이션/필터 제공.
2. 상세: 직업 정보 옆에 해당 제출의 사진/PDF 미리보기. 관리자가 허가받은 제출만 짧은 유효기간 다운로드 URL로 조회.
3. 판정: 승인 / 반려 또는 보완 요청. 사유 코드를 고르고 사용자에게 표시할 짧은 안내를 작성.
4. 저장: 검토자·검토 시각·대상 제출 버전·판정·사유 기록. 두 운영자의 동시 판정은 버전 검사로 충돌을 알림.
5. 재제출: 새 제출을 만들고 이전 판정 이력을 보존. 이전 서류를 덮어써서 심사 대상이 바뀌지 않도록 함.

권장 상태: `NOT_SUBMITTED / PENDING / IN_REVIEW / VERIFIED / REJECTED`. 재제출은 새로운 제출 건의 PENDING. 자료 삭제나 직업 변경 시 기존 인증을 유지할지 취소할지 명시적으로 정한다.

API 제안:

- 관리자: `GET /admin/job-verifications?status=PENDING&cursor=...`
- 관리자 상세: `GET /admin/job-verifications/{submissionId}`
- 판정: `PATCH /admin/job-verifications/{submissionId}` — decision, reasonCode, message, version
- 본인: `GET /my-page/job-verification` — 상태·제출/판정 시각·보완 사유
- 재제출/철회: 본인 전용 API에서 소유자와 제출 버전을 검증. 가입 시 제출도 같은 서비스 사용.

공개 프로필에는 `jobVerified: true/false` 또는 VERIFIED 여부만 반환한다. 제출만 한 사람에게 승인 마크를 주지 않는다. 현행 RN은 '서류 제출'만 표시하고 있으므로 실제 승인 계약이 제공된 다음 인증 마크로 전환한다.

현재 SecurityConfig는 `/admin`에 관리자 역할 조건을 명시하지 않고 일반 인증 규칙을 적용한다. 운영 기능을 추가할 때 관리자 역할 검사를 서버에 먼저 넣어야 한다. 운영 화면은 별도 인증과 서버 권한 검사, 조회·판정 기록을 갖춰야 한다. 서류 다운로드 주소를 일반 회원 API나 일반 로그로 노출하지 않는다. 자료 보관/삭제 정책과 사용자 안내는 출시 전 운영 정책으로 결정한다. 승인 이력과 서류 파일의 보관 기간은 구분해서 정한다.

검수: 다른 회원/일반 계정의 접근 차단, 승인 전 마크 없음, 재제출·직업 변경, 동시 판정, 서명 URL 만료 후 재발급, 자료 열람 및 판정 이력.

참고:

- [AWS: S3 presigned URL](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html): 버킷을 공개하지 않고 시간 제한 다운로드 권한 제공.
- [OWASP: Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html): 서버에서 매 요청의 자료 접근 권한 검사.

## 구현 우선순위

1. 이미지 다운로드 URL 계약과 AI introAudio 생성부터 해결. 사용자가 즉시 확인할 수 있는 주요 기능의 막힘을 해소한다.
2. 학습/미리듣기 상태·파일 ID·만료 시간 계약을 추가하고 RN에 연결한다.
3. 직업 인증 상태/관리자 API → 작은 운영 웹 화면 → 본인 심사 안내/공개 인증 마크 순서로 진행한다.
4. 알림 발송 선호도와 음성 설정의 실기기 소리 출력을 검수한다.

이번 RN 변경은 네이티브 의존성·플러그인을 추가하지 않으므로 prebuild/CocoaPods 재설치가 필요하지 않다.

## 통화 소리 설정 — 이번 RN UX 보완

- `상대 목소리 크기`: 0~100%, 10% 단위 조절과 작게(25)/보통(50)/크게(100) 선택. 0%는 소리 끔으로 명확하게 표시한다. 저장 중 제어를 잠그고 실패하면 이전 값과 재시도 가능한 오류를 유지한다.
- 적용 범위: AI 통화의 수신 오디오 트랙, 공개 프로필/트윈 미리듣기, 소리 테스트. 서버 값이 아직 없으면 기존 재생 볼륨(1)을 유지하고 통화를 막지 않는다. 설정 화면에서는 조회 없이 임의의 값으로 PATCH하지 않는다.
- `소리 확인`: 앱에 포함된 약 9초의 한국어 AI 안내 음성을 현재 연결된 이어폰/스피커에서 재생한다. 네트워크 요청이나 통화 시간 차감이 없다. 0%에서는 먼저 음량을 올리도록 안내하고, 화면 이탈·백그라운드에서 재생을 멈춘다.
- `마이크 사용`: 화면 진입·복귀 시 권한만 확인한다. 허용 버튼을 누를 때만 권한을 요청한다. 이미 허용되어 있거나 다시 요청할 수 없을 때도 항상 기기 설정 열기를 제공한다. 사용자는 OS 설정에서 허용/차단을 바꾸고 앱으로 돌아오면 갱신된 상태를 확인한다. 권한 확인 과정에서 녹음하지 않는다.
- 기존 `opponentSpeechSpeed` 필드는 API 호환성 때문에 읽고 PATCH에 보존한다. RN에서 속도 변경 UI·재생 속도 조절은 하지 않는다. 백엔드/AI에 속도 기능 변경을 요청할 필요는 없다.
- 작은 화면·큰 글자에서는 카드 높이를 제한하지 않고 선택 버튼을 줄바꿈한다. 최소 48pt 터치 영역과 필요한 경우의 스크롤을 유지한다.
- 후속 스크롤 보완: 부유형 하단 메뉴의 실제 높이·안전 영역·바닥 간격을 메인 레이아웃에서 공유한다. `ScreenLayout`은 메뉴 위에 마지막 버튼을 올릴 수 있는 하단 여백을 자동으로 확보한다. 기존 화면이 요청한 더 넓은 여백은 유지하고, 메인 탭 밖 화면은 기존 여백을 유지한다. 통화 소리 설정의 ‘마이크 설정 열기’가 메뉴에 가려지는 문제와 동일한 계정·알림 화면의 하단 접근 문제를 보완했다.

## 이번 RN 변경 검증

- 전체 Jest: 63개 묶음, 364개 테스트 통과. 설정 저장 실패·연속 저장·계정 변경·저장 중 재조회 경합, 수신 볼륨 적용, 안내 음성 반복 재생·백그라운드 정지, 마이크 권한 요청·이미 허용된 권한 변경·설정 복귀 갱신·설정 열기 실패 복구를 검증했다. 알림 관리 시트의 목록 조회·방별 변경·읽기/저장 실패 복구·기기 알림 권한 표시·Android 설정 복귀 등록도 검증했다. 계정 화면의 이메일·미리보기·테마·도움말 연결과 닉네임 입력 보존/재시도, 로그아웃·탈퇴 중복 요청 및 계정 변경 방어도 확인했다. 후속 레이아웃 테스트는 iOS/Android 안전 영역 및 메뉴 높이 변경에 따른 하단 여백 갱신과 마이크 설정 열기 호출을 확인했다. 테스트가 네이티브 화면의 실제 물리 배치를 검증하는 것은 아니다.
- 신규 변경으로 생긴 ESLint·TypeScript 오류 없음. 공용 `useAICallFlow`에는 기존 타입 오류와 ESLint 경고 4개가 남아 있으며, 이번 수정은 볼륨 훅 import·호출 두 줄이다. 프로젝트 전체의 기존 타입 오류는 유지했다.
- iOS/Android 프로덕션 JS·Hermes 번들 생성 확인. 네이티브 실기기 소리 출력·배포 서버 데이터는 직접 검증하지 않았다.
- 기존 historyService/homeService 테스트가 가져오는 Sentry 정리 타이머로 Jest 종료가 지연되는 것은 `--detectOpenHandles`로 확인했다. 최종 전체 테스트는 `--forceExit`로 종료했다. 신규 프로필 테스트에서는 해당 타이머를 모킹해 분리했다.
- 실기기 확인 필요: 사진 등록→프로필→공개 미리보기, 사진 조회 실패→재시도, 미리듣기 끝까지 재생→다시 듣기, 볼륨 0/25/50/100에서 실제 통화·안내 음성·미리듣기 비교, 블루투스 이어폰 전환, 마이크 권한 거부→기기 설정 허용→앱 복귀, 앱 전환·복귀, 느린 네트워크·URL 만료, 큰 글자/작은 기기의 버튼 줄바꿈.

## 통화 음량 후속 점검

iOS Expo AudioRecorder의 `prepare`는 오디오 세션을 `.playAndRecord / .default`로 재설정한다. 통화가 연결돼 InCallManager가 `videoChat`을 설정한 뒤 이 준비가 실행되므로 기본 스피커 경로가 풀릴 수 있었다. 녹음 준비 성공·실패 후 현재 통화에만 자동 영상통화 경로를 재적용하며, 준비 도중 선택한 스피커 설정도 유지한다. 종료된 통화의 늦은 준비 완료는 녹음/출력 전환을 시작하지 않는다. Android에서는 Expo 오디오 모드를 호출하지 않고 기존 InCallManager의 통신 모드를 유지한다.

소리 테스트·목소리 미리듣기는 녹음 모드를 해제하고 재생 모드를 명시한다. 통화 설정의 상대 목소리 크기는 기존과 같은 값으로 재생/원격 스트림에 적용한다. 기기 통화 볼륨과 미디어 볼륨, AI 원본 음성의 크기는 다르므로 테스트 음성과 실제 통화의 물리적인 음압이 같다고 보장하지 않는다. 실제 iOS/Android에서 스피커·유선·Bluetooth 연결/해제, 녹음 준비 실패 및 종료 도중 취소를 검수해야 한다.

근거: 설치된 expo-audio `ios/AudioRecorder.swift`, react-native-incall-manager `ios/RNInCallManager/RNInCallManager.m`, [Apple videoChat 문서](https://developer.apple.com/documentation/avfaudio/avaudiosession/mode-swift.struct/videochat). Apple은 videoChat에서 Bluetooth 및 기본 스피커 옵션을 자동 적용한다고 설명한다.
