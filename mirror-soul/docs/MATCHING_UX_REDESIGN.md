# 매칭 UX 개편

작업 브랜치: `codex/matching-ux-redesign`
출발점: `origin/main`의 `541933e` (PR #196 병합). RN만 수정하며 백엔드·AI·인프라는 변경하지 않는다.

## 분석과 설계

기존 화면은 가로 신청 카드와 화면 아래의 공통 ‘스킵’, ‘채팅’ 버튼을 연결했다. 실제 API는 거절과 수락이므로 버튼이 일으키는 결과를 예측하기 어려웠고, 목록 갱신 후 선택 인덱스가 바뀌면 다른 신청을 처리할 위험도 있었다. 고정된 카드 높이, 작은 문구, 큰 여백은 긴 메시지와 큰 글자 설정에서 불리했다.

개편 화면은 **받은 신청 → 메시지·트윈 대화 참고 정보 확인 → 수락 → 메시지방**을 기본 흐름으로 삼는다. 여러 신청을 세로 목록으로 비교하며 모든 행동은 신청 ID에 연결한다. 거절은 상세 화면에서 확인 후 진행한다. ‘메시지’ 탭은 실제 메시지방과 읽지 않은 대화를 보여준다.

## 구현한 내용

- 받은 신청 목록: 이름·사진·신청 시점·메시지, 명확한 ‘수락하고 대화하기’ 버튼. 목록의 긴 메시지는 3줄로 요약하고 상세에서 전체를 읽는다.
- 신청 상세: 전체 메시지, 서버가 제공하는 대화 요약·요약 항목·공감도, 수락 후 첫 메시지로 이어지는 동작 안내. 분석 데이터가 없으면 자료가 없다고 안내하며 처리 중으로 추측하지 않는다.
- 먼저 상대 트윈과 통화하기: 실제 남은 시간을 조회하고 시간 부족·조회 실패를 안내한다. AI 트윈 통화와 시간 사용을 미리 설명한다. 통화 후 새 신청을 보내지 않고 받은 신청으로 돌아오며 같은 신청으로 반복 통화해도 상세가 다시 열린다.
- 메시지함: 전체/안 읽음 필터, 읽지 않은 메시지 수, 마지막 메시지·시점·방 알림 꺼짐 표시. 실제 방 ID로 이동한다.
- 추천 노출 설정: ON/OFF의 의미와 기존 신청·메시지를 확인할 수 있다는 점을 설명한다. 조회 중·조회 실패·저장 중 상태를 구분한다.
- 요청 실패·빈 목록·로딩·이전 목록을 유지하는 갱신 실패를 구분한다. 화면 진입·앱 복귀·직접 새로고침으로 최신 데이터를 조회한다.
- 중복 탭을 막고, 처리 중 취소·다른 신청 처리를 제한한다. 수락 성공 후 메시지 목록 재조회가 실패해도 응답의 메시지방 ID로 바로 이동한다.
- 받은 신청·추천 노출 쿼리를 계정별로 나누고 취소 신호를 전달한다. 계정 전환 후 이전 작업이 새 계정 캐시나 화면에 적용되지 않도록 확인한다. 메시지방 쿼리 키는 기존 웹소켓·읽음 처리와의 호환성을 유지한다.

## 반응형과 접근성

리스트와 상세는 고정 높이 대신 내용에 맞춰 늘어난다. 공통 `useLayout`으로 태블릿 콘텐츠 폭을 제한하며, 노치·하단 안전 영역과 실제 하단 탭바 높이를 고려한다. 작은 화면·큰 글자에서는 추천 노출 제목과 토글을 위아래로 배치한다. 탭·필터는 줄바꿈을 허용하고 행동 영역은 최소 48pt이다. 상세는 안전 영역 내 높이를 제한한 스크롤을 제공하므로 긴 메시지·요약도 끝까지 볼 수 있다. 사진 로드 실패에는 이름 기반 기본 아바타를 제공한다.

## 기록·성장과 디자인 통일

현재 백엔드 `cded928`의 HomeController·RecommendService·RecommendationDetailService·SwipeService·MeetingService를 읽어 계약을 재확인했다.

기록·성장의 중립적인 테마 배경, 32pt 둥근 카드, 시안·퍼플 포인트, 기존 `FontFamily.sans`를 발견·매칭에도 사용한다. 상단은 `MainTabHeader`로 왼쪽 정렬·24pt 한글 제목을 공유한다. 기록과 성장은 헤더만 ‘기록’·‘성장’으로 바꾸고 본문과 데이터 흐름은 유지한다. 매칭만 사용하던 별도 폰트·색상 로더는 제거해 탭 이동 시 서체와 분위기가 이어지도록 했다.

카드의 이름·메시지와 주요 행동에 시각적 우선순위를 둔다. 목록에서는 반복되는 설명을 덜어내고, AI 요약은 서버가 실제로 제공한 경우에만 표시한다. 통화 시간 사용과 거절 확인은 결정 시점에 유지한다. 추천 노출 설정의 안내는 정보 버튼을 누를 때 펼친다. 카드와 버튼은 내용에 따라 늘어나며 작은 화면·큰 글자에서 자연스럽게 줄바꿈하거나 세로 배치로 전환한다.

깔끔함과 탭 간 일관성을 위해 다섯 메인 탭 모두 공통 한글 제목을 사용한다. 프로필의 별도 ‘MY SPACE’ 문구와 매칭의 탭 이름을 반복하는 소제목을 제거했다. 매칭은 제목 → 추천 노출 설정 → 받은 신청/메시지 → 목록 순서로 구성한다. 상단 여백은 안전 영역 + 12pt, 최소 24pt 기준으로 맞추며 안전 영역을 이미 적용한 화면에서는 중복으로 더하지 않는다. 좌우 여백은 기존 공통 24pt를 유지한다. 색상은 공통 테마와 기존 Colors 토큰을 재사용하며 화면 전용 팔레트를 추가하지 않는다. 기록·성장의 본문 구성과 API 동작은 유지한다.

발견도 같은 헤더와 작은 정보 카드로 시간·지역을 표시한다. 지역은 실제 `includedRegionIds` 개수로 주변 동네 수를 표시한다. 추천 상태에는 서버에서 확인할 수 없는 분석 문구를 표시하지 않는다. 카드의 ‘트윈과 통화하기’는 기존 최신 잔여 시간 확인 시트를 그대로 사용한다. 스와이프와 함께 이전·다음 버튼을 제공하며, 다음은 기존 PASS API, 이전은 서버 기록을 취소하지 않는 로컬 탐색이다. 지난 카드의 늦은 애니메이션 콜백이 다음 카드를 다시 넘기지 못하도록 UUID를 확인한다.

추천 0건은 실제 빈 목록으로 표시한다. 개발용 예시는 개발 모드에서 사용자가 명시적으로 선택한 경우에만 표시하고 API 통화·스와이프를 실행하지 않는다. 다음 페이지 조회 실패에는 해당 페이지 재시도를 제공하며 무한 자동 재시도를 막는다. 동기 락으로 새로고침 연타를 막고 조회 실패 시 현재 카드를 유지한다.

## 실제 서버 계약과 확장 범위

API 스냅샷 `.claude/artifacts/backend-schema.json`, `analysis-report.md`를 먼저 확인하고 필요한 `MeetingService` 등 실제 소스를 재확인했다.

| 항목 | 현재 서버 동작 | 이번 RN 처리 / 향후 필요 사항 |
| --- | --- | --- |
| 추천·상세 | `GET /home/recommend`: `page/size/hasNext`, 노출 이력이 있는 상대만 상세 조회 가능 | 실제 추천 데이터만 기본 표시. 서버 노출 권한과 통화 확인 시트 유지 |
| 직업 서류 | `jobCertificationSubmitted`는 S3 객체 키 존재 여부 | 인증 완료 마크로 표현하지 않고 서류 제출로 표시 |
| 발견 넘김 | `POST /home/recommendations/{uuid}/swipe`: PASS 기록, LIKE 없음 | 다음·스와이프는 동일 API. 이전은 로컬 탐색이며 서버 PASS 취소로 표현하지 않음 |

| 수락 | `POST /match/meeting/requests/{id}/accept`: 방 생성, 신청 메시지를 첫 메시지로 저장, 방 ID 반환 | 반환된 방 ID로 이동. 이미 처리된 신청 오류는 목록 재조회 |
| 거절 | `POST /match/meeting/requests/{id}/reject`: PENDING 목록에서 제거 | 최종 행동임을 확인하고 성공 후 제거 |
| 양방향 중복 신청 | 한 사용자 쌍에 진행 중 신청이 있으면 반대 방향 신청도 차단 | 받은 신청에서 트윈 통화 후 중복 생성 없이 기존 신청 복귀 |
| 신청자 전체 프로필 | 별도의 신청자 프로필 조회 API 없음. 추천 상세는 추천 권한 확인 필요 | 받은 신청 응답으로 구성. 확장하려면 신청 ID로 권한 확인하는 프로필 조회 계약 필요 |
| 보낸 신청·취소 | 조회·취소 API 없음 | 이번 화면에는 추가하지 않음. 향후 상태·허용 행동을 서버가 제공하는 보낸 신청 조회와 취소 API 필요 |
| AI 요약 처리 상태 | 선택적 요약·공감도만 제공 | 누락을 처리 중이라고 표시하지 않음. 상태·실패·갱신 시점을 표시하려면 서버 계약 필요 |
| 추천 노출 OFF | 추천 제외와 다른 사용자의 새 트윈 통화를 차단. 기존 신청·대화는 유지 | 신규 신청까지 모두 차단한다고 약속하지 않음 |
| 신청 목록 규모·시각 | 현재 전체 조회, 날짜에 시간대가 명확하지 않을 수 있음 | 규모가 커지면 커서 페이지네이션, 날짜는 시간대 오프셋을 포함한 ISO 8601 권장 |

## 검증과 실제 기기 확인

새 테스트는 신청 ID에 따른 수락, 연속 탭, 거절 확인·실패·재시도, 메시지 목록 조회 실패 후 이동, 읽지 않은 메시지 필터, 통화 전 시간 확인, 반복 통화 후 기존 신청 복귀, 계정 변경과 오래된 조회 결과 무효화, 중복 신청 UI 방지를 검증한다.

전체 Jest **67개 묶음·382개 테스트**가 통과했다(이번 작업의 새 테스트 18개 포함). iOS/Android JS 번들 생성에 성공했고, 변경 파일의 TypeScript 새 오류와 ESLint 오류·경고는 없었다. 저장소 전체에는 기존 TypeScript 오류가 남아 있다.

실제 기기 검증은 별도로 필요하다. 특히 320~360pt 휴대폰, 큰 글자 설정, 가로 모드·태블릿, 긴 닉네임·메시지·요약, 하단 탭바 끝까지 스크롤, 네트워크 끊김·복귀, 사진 URL 만료, 상세에서 트윈 통화 후 반복 복귀를 확인한다. 이 환경의 MLKit 제약 때문에 iOS 시뮬레이터 검증으로 대체할 수 없다.
