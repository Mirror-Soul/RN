# 선택 프로필 사진 — 2026-10-03

작업 브랜치: `codex/profile-photo-onboarding`. RN 구현이며 백엔드·AI·인프라 submodule은 수정하지 않았다.

## 제품 결정

- 사진 없이 가입 완료, 상대 둘러보기, 트윈 통화와 상대 추천 노출을 허용한다. 사진 삭제 후에도 동일하다. 다른 기존 이용 조건은 유지한다.
- 본인 얼굴이 잘 보이는 사진을 권장한다. 자동 얼굴/본인 판별이 없으므로 실제 업로드는 차단하지 않는다.
- 가입 Step2와 가입 후 프로필에서 같은 편집 흐름을 사용한다. 별도 ‘사진 등록’ 버튼으로 저장한다.
- 최종 사진 한 장을 사용한다. 상세 사진과 크롭은 너비:높이 4:5, 발견 카드 4:3, 아바타 원형이다.
- 프로필 탭은 내 사진·닉네임 → 사진 관리·공개 미리보기·트윈 상태 → 남은 대화 시간·충전 → 계정 설정 순서로 배치한다. 큰 사진은 공개 미리보기에서 확인한다.
- 공개 미리보기는 본인 API 데이터로 상대 상세 레이아웃을 사용한다. 이메일·계정 설정은 제외하며, 추천 API와 본인에게 통화하는 버튼을 사용하지 않는다.

## 등록과 저장

`앨범/촬영 → 방향·크기 정리 → 4:5 이동/확대 크롭 → 상세·카드·원형 미리보기 → 사진 등록`

1. `expo-image-picker`의 시스템 선택기를 사용한다. 전체 앨범 접근을 먼저 강요하지 않고 촬영 시 카메라 권한을 요청한다.
2. `expo-image-manipulator`로 실제 이미지 방향·픽셀 크기를 정리하고 JPEG를 만든다. HEIC의 이름이나 MIME만 JPEG로 바꾸지 않는다.
3. 실제 변환 파일의 크기를 확인한다. 0 초과 / 5 MiB 이하이며 JPEG 압축으로 한도를 맞추지 못하면 선택을 다시 안내한다.
4. `POST /files/presigned-url`에 `{fileName:'profile.jpg', contentType:'image/jpeg', directory:'profile-images'}`를 보낸다.
5. 기존 바이너리 PUT 업로더로 S3에 전송한다. API용 Bearer 헤더를 S3에 전달하지 않는다.
6. `PATCH /my-page/profile-image`에 발급받은 `{objectKey}`를 보낸다.
7. 성공 후 본인 프로필·소개 캐시의 사진 필드만 갱신하고 재조회한다. 이름·이메일·소개를 덮어쓰지 않는다.

가입의 닉네임·지역·직업 저장과 사진 등록은 독립적이다. 사진 성공 후 기본 정보 저장에 실패해도 사진을 재업로드하지 않는다. 사진이 없어도 기존 Step2 유효성 검증에는 영향이 없다.

PUT 실패 시 PATCH를 호출하지 않는다. PUT 성공 후 PATCH 실패에는 같은 파일/키로 연결만 재시도한다. PATCH 응답이 유실된 경우 본인 조회 URL에서 키를 확인해 저장 여부를 복구한다. 사진 등록·삭제는 사용자별 동시 작업 잠금과 즉시 탭 잠금을 사용하며 로그아웃 이후의 이전 작업이 새 세션에서 연결/캐시 갱신을 하지 않도록 확인한다.

사진 준비·업로드·프로필 저장 단계를 구분하고 업로드 중에는 실제 전송 바이트로 퍼센트를 표시한다. 전체 전송량이 제공되지 않으면 로딩 안내를 유지한다. 처리 중 닫기는 막고 업로더의 60초 타임아웃으로 복구한다. 저장 전 나가면 확인 후 편집만 취소하고 기존 사진을 유지한다. 생성한 편집용 임시 파일은 편집 종료 시 정리한다.

## 변경·삭제·표시

- 새 사진도 등록과 같은 흐름을 사용하고 성공 전까지 기존 공개 사진을 유지한다.
- 삭제 확인 후 `DELETE /my-page/profile-image`를 호출한다. 성공 시 기본 아바타로 돌아간다. 응답 유실 시 GET으로 제거 여부를 확인한다.
- 현재 DELETE는 프로필 연결을 제거하며 S3 파일 자체는 남긴다. UI에서는 영구 파일 삭제로 표현하지 않는다.
- 원본은 서버에 별도로 보관하지 않는다. 편집 세션 안에서는 다시 구도를 조정할 수 있지만 앱을 다시 연 뒤 잘려 나간 영역까지 복원하려면 원본을 재선택해야 한다.
- 발견·상대 상세·만남·채팅·내 소개에서 URL 변경 시 이전 다운로드 실패 상태를 초기화한다. 통화 기록의 다운로드 실패도 대체 이미지로 복구한다.
- 다른 사용자의 사진은 해당 사용자 앱에서 재조회할 때 갱신된다. 현재 사진 변경 실시간 이벤트가 없으므로 다른 기기의 기존 캐시까지 즉시 지워진다고 약속하지 않는다.

## 검증 및 남은 배포 확인

자동 테스트: crop 픽셀 좌표·경계, 기존 캐시 필드 보존, 공개 필드 분리, PUT 실패, PATCH 부분 실패/응답 유실, 중복 저장, 로그아웃, 삭제, 5 MiB 초과 파일 차단을 검증한다. 기존 profileService 테스트도 포함한다.

수정 파일의 lint와 신규 타입 오류를 확인한다. 프로젝트 전체에는 기존 SVG 모듈 선언·라우팅·통화 관련 타입 오류가 있으므로 전체 tsc 성공을 주장하지 않는다.

실기기 빌드/촬영/HEIC 디코딩/멀티터치/권한 선택/실제 API 업로드는 아직 검증하지 않았다. 새 네이티브 모듈과 권한 설정이 추가되었으므로 **두 플랫폼 모두** 기존 네이티브 프로젝트를 재생성하고 재빌드해야 한다. `expo start`만으로는 반영되지 않는다. 로컬 native 디렉터리는 이 작업에서 재생성하지 않았다.

```sh
npx expo prebuild --clean
npx expo run:android -d
# 또는 iOS 실기기:
npx expo run:ios -d
```

기존 MLKit 제약으로 Apple Silicon iOS 시뮬레이터는 검증 전제로 삼지 않는다. iOS 설치가 기존 LockdowndClient 오류로 실패하면 저장소 가이드의 `ios-deploy` 절차를 사용한다.

배포 전 백엔드 확인이 필요하다. 현재 소스의 V37 migration 두 개 충돌은 실제 적용 이력을 확인해 해소해야 한다. API의 서명 없는 S3 이미지 주소와 인프라의 공개 접근 차단이 실제 배포에서도 일치하면 사진 GET이 실패하므로 전달 URL 계약을 보완해야 한다. 이 RN 변경은 두 백엔드 문제를 해결하거나 실제 AWS 배포를 검증한 것이 아니다.

추가 인터뷰에서 공개 미리보기와 트윈 상태를 구분하기로 확정했다. 기존 `profile-introduction` 경로는 유지하고 화면 제목·내용을 ‘트윈 상태’로 정리했다. 싱크로율·음성 학습 횟수/날짜·학습된 성향·트윈 목소리·성장 진입을 표시하고 공개 사진·지역·직업·자기소개는 공개 미리보기에서 확인한다. 트윈 상태 조회 실패를 0회/0%로 표시하지 않으며 READY 이전의 null 싱크로율은 준비 중으로 표시한다. 공개 상세의 준비 전 nullable 싱크로율도 기존 계약대로 유지한다.

## 사진 선택 오류 수정과 가입 화면 다듬기

사용자가 사진 선택 직후 `Cannot read property … undefined`를 보고했다. 전체 오류 문자열과 기기 정보가 아직 없어 단일 원인은 확정하지 않았다. 확인한 로컬 `ios/Podfile.lock`과 `ExpoModulesProvider.swift`에는 새 `ExpoImageManipulator`가 포함되어 있지 않다. 이 빌드로 사진 편집을 사용하려면 위의 prebuild·재빌드가 필요하다.

- 네이티브 편집 모듈의 존재와 호환성을 먼저 확인하고, 확인 후에만 패키지를 로드한다. 미포함 빌드에서도 가입 화면 전체가 깨지지 않고 앱 업데이트 안내가 표시된다.
- 취소·누락된 assets·빈 URI를 구분하고, 디코더가 반환한 크기도 검사한다. 로컬 사진 처리의 개발용 예외 문자열은 사용자에게 직접 표시하지 않고 로그와 친화적인 안내로 나눈다.
- 크롭 제스처의 터치 배열이 없거나 비어 있는 이벤트는 무시한다. 이미지 가공이 끝나거나 실패하면 네이티브 이미지 참조를 해제한다.
- 가입 사진 카드의 선택 배지·공개 위치·별도 얼굴 스캔 안내를 나눴다. 본문은 14px/22px, 주요 터치 영역은 44~52px으로 확보하고 공통 폰트를 사용한다.
- 편집의 두 단계를 표시하고 미리보기·등록·나중에 등록을 구분한다. 밝은 테마의 주요 버튼 글자색 대비도 수정했다.
- 가입 기본 정보의 간격과 안내를 정리하고 ‘완벽한 매칭’·‘3배 보장’ 표현을 제거했다. 사진과 직업 서류는 선택 사항으로 유지한다.

추가 자동 검증은 비정상 선택 결과·취소·모듈 누락·JPEG 변환과 참조 해제·압축 재시도·빈 터치 이벤트·미리보기 후 별도 등록을 포함한다. 실기기에서의 선택·크롭·저장은 재빌드 후 별도로 확인해야 한다.

사용자는 재빌드·설치 후 사진 등록이 동작한다고 확인했다. 이후 인터뷰에서 현재 흐름은 편하고 완성도를 조금 높이고 싶다고 답했다. 선택·편집·미리보기·별도 등록 순서를 유지하면서 아래 마무리 경험을 개선했다.

- 등록 성공 시 편집기를 닫고 기존 전역 토스트로 알린다. 추가 확인 팝업을 띄우지 않는다. 등록된 사진에는 ‘사진 등록됨’ 표시를 남기며, 사진이 있는 회원에게 건너뛰라는 안내를 반복하지 않는다.
- 사진이 없는 상태와 다운로드 실패를 구분한다. 불러오는 동안 로딩을 표시하고, 실패한 아바타를 누르면 같은 사진의 다운로드를 다시 시도한다. 이전 재시도의 늦은 실패 이벤트가 새 시도를 덮어쓰지 않도록 한다.
- 가입 사진 카드에는 이미지 표시 실패 안내를 추가한다. 다운로드 실패만으로 사진 등록 상태를 지우지 않는다. 사진 삭제 성공은 짧게 알리고 실패 시 기존 등록 상태를 유지한다.
- RN 코드만 변경했다. 추가 의존성·네이티브 설정 변경이 없어 이미 새 모듈을 포함한 개발 앱에서는 Metro 새로고침으로 반영할 수 있다.

추가 테스트는 사진 없음/로딩/성공/실패 구분, 실패 후 재시도, URL 변경·삭제 시 상태 초기화, 등록·삭제 성공 알림과 실패 시 상태 유지를 검증한다. 실제 화면에서의 알림 위치와 로딩 표시는 실기기에서 추가 확인이 필요하다.

## 프로필 상단과 사진 관리 버튼 정리

사용자의 추가 요청에 따라 내 프로필 카드를 가장 위로 옮겼다. 서버의 실제 닉네임과 사진을 표시하고, 남은 대화 시간·충전과 설정은 그 아래에 유지한다. 닉네임은 최대 두 줄까지 표시한다.

사진 관리 영역은 닉네임 아래에 간격과 구분선을 두고 배치한다. 변경·삭제 버튼에는 각각 테두리와 아이콘을 제공하고, 좁은 화면에서는 줄바꿈하며 시스템 글자 크기가 큰 경우 세로로 배치한다. 고정 높이 대신 최소 터치 높이와 텍스트 줄바꿈을 사용한다. 공개 미리보기·트윈 상태 버튼과의 간격도 확보한다.

이번 변경은 RN 화면·스타일만 수정하므로 추가 설치나 네이티브 재빌드 없이 Metro 새로고침으로 반영한다. 실제 기기의 화면 배치 확인은 별도로 필요하다.

## 크롭·전송·사진 관리 추가 개선

- 크롭 화면 아래에 추천 카드(4:3)와 원형 아바타 미리보기를 동시에 표시한다. 실제 최종 크롭 좌표를 사용하고, 이동·확대 때 이미지를 다시 저장하지 않고 화면 좌표만 갱신한다.
- 편집 중 90도 회전을 제공한다. 매번 선택 당시의 정규화 원본에서 회전하고 새 방향의 크기로 크롭한다. 네 번째 회전은 원본으로 돌아오며, 구도 다시 맞추기에서는 회전 방향을 유지한다. 회전용 임시 파일과 네이티브 참조를 정리한다.
- S3 업로더에 선택적 전송 바이트 콜백을 추가했다. 기존 음성·얼굴 스캔 업로드 호출은 그대로 지원한다. 총량이 유효한 경우에만 진행률을 표시하며 실패한 이전 시도의 늦은 이벤트를 무시한다. 전송 완료와 프로필 API 저장 완료를 구분한다.
- 업로드 실패 시 편집 결과를 유지하고 ‘사진 등록 다시 시도’로 동일 파일을 재전송한다. PUT 성공 후 연결만 실패했다면 기존 동작대로 PATCH만 재시도한다.
- 가입 화면과 프로필 탭에서 등록된 작은 사진을 누르면 큰 사진을 확인하고 변경·삭제로 이어갈 수 있다. iOS는 확대 Modal이 실제 닫힌 뒤 사진 선택 메뉴·삭제 확인을 표시한다.
- 등록 성공 토스트와 ‘사진 등록됨’ 표시를 유지한다. 확대 사진의 다운로드 실패는 등록 상태와 구분하고 ‘다시 불러오기’를 제공한다. 실패했던 이전 다운로드의 늦은 이벤트가 재시도를 덮어쓰지 않는다.

전송 바이트·타임아웃·실패 후 재시도, 크롭 좌표의 카드/원형 투영, 회전 방향과 최종 크롭, 사진 확대의 다운로드 재시도와 Modal 종료 후 작업을 자동 테스트한다. 실제 iOS/Android의 회전 디코딩, 네트워크 전송 이벤트와 화면 배치는 실기기에서 확인이 필요하다. 네이티브 설정이나 의존성은 추가하지 않았다.
