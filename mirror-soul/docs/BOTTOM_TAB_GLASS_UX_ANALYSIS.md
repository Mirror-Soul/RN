# 하단 탭 글래스 UI/UX 검토

검토일: 2026-10-06. 대상: `codex/call-entry-connected-ux`의 RN 코드.
아래 분석은 구현 전 상태를 기준으로 작성했다. 이후 사용자의 구현 요청에 따라 RN에 적용한 내용은 문서 마지막에 별도로 기록했다. 실제 기기 렌더링은 검증하지 않았다.

## 권장 방향

기록·성장·발견·매칭·프로필의 순서와 항상 보이는 이름은 유지한다. 하나의 은은한 반투명 바에 선택한 탭만 옅은 시안색 캡슐로 강조하는 구성이 적합하다.

- 바: 밝은 테마는 우윳빛, 어두운 테마는 차콜색 블러. 가는 테두리와 낮은 그림자만 사용한다.
- 선택 탭: 선명한 시안색 원과 발광 효과 대신 옅은 시안 면, 또렷한 아이콘, 조금 굵은 이름을 조합한다.
- 아이콘: 기존 화면에서 쓰는 로컬 Phosphor 계열과 통일한다. 기록은 시계/기록, 성장은 성장/새싹, 발견은 나침반, 매칭은 두 사람/대화, 프로필은 사람 모양을 권한다. 현재 로컬 아이콘 목록에 없는 도안은 라이선스를 확인하고 같은 계열 SVG를 추가해야 한다.
- 글꼴: 현재 하단 바는 Inter 지정이지만 한국어는 폰트 폴백에 영향을 받는다. 앱에서 이미 로딩하는 SUITE Medium/SemiBold를 사용하면 한국어 이름의 인상이 본문과 맞는다.
- 이름 크기: 현재 10에서 기본 11~12pt를 시안 기준으로 검토하되, 시스템 글자 확대를 존중하고 실제 높이를 측정한다.
- 누름 피드백: 색 변화 중심으로 단정하게 구성한다. 탭 높이와 아이콘 위치를 바꾸지 않는다. 반복 확대·바운스·강한 발광은 넣지 않는다.
- 글래스 표면은 공통 바 한 겹만 둔다. 다섯 개의 개별 블러 표면을 중첩하면 정보가 복잡해지고 Android 렌더링 비용이 늘 수 있다.

이는 코드와 공식 지침을 바탕으로 한 설계 제안이며, 시각 선호는 실제 시안에서 확인해야 한다.

## 현재 코드에서 확인한 사항

| 항목 | 확인 결과 | 개편 시 처리 |
| --- | --- | --- |
| 배경 | `BottomNavbar.tsx`에 이미 `expo-blur` 적용 | 기존 기반을 재사용하고 면·테두리·그림자를 조정 |
| 선택 표시 | 44pt 시안 원, 시안 라벨, 발광 그림자 | 옅은 캡슐과 테마별 읽기 쉬운 글자색 |
| Android 블러 | `experimentalBlurMethod`를 지정하지 않음. 설치 버전 기본값은 `none` | 지금은 실제 블러가 아닌 반투명 대체 화면. 성능 검증 전에는 밀도 있는 반투명 표면을 권장 |
| 작은 화면 | 바 밖 좌우 24pt, 바 안 좌우 20pt, 테두리 1pt | 작은 화면에서는 여백을 줄여 탭별 최소 터치 너비 확보 |
| 이름 | 10pt / 줄 높이 14, 폭·최소 터치 너비 보장 없음 | 글자 확대에서 줄바꿈/높이 증가를 반영 |
| 아래 안전 영역 | `insets.bottom + 16` 위에 바를 배치 | 홈 인디케이터/Android 내비게이션 영역을 계속 반영 |
| 좌우 안전 영역 | 바에서 `insets.left/right`를 반영하지 않음 | 회전·창 크기 변경 시 사용 가능한 안전 너비를 기준으로 계산 |
| 콘텐츠 가림 높이 | `onLayout`으로 실측하여 Context로 전달 | 측정 구조 유지, 레이아웃 전 초기값도 안전하게 처리 |
| 화면별 하단 여백 | 발견·매칭·프로필은 실측 값을 사용. 기록·성장은 고정 `bottom inset + 100` 사용 | 다섯 탭 모두 같은 실측 가림 높이와 여유 간격 사용 |
| 접근성 | 탭 역할, 이름, 선택 상태 있음 | 유지하고 투명도 줄이기·동작 줄이기·테마 변경에 대응 |
| 탐색 이벤트 | `navigation.navigate()`만 호출 | 커스텀 탭바에서 `tabPress`/`tabLongPress` 전달도 검토. 같은 탭 재선택 동작은 별도 정책으로 결정 |
| 키보드 | 사용자 정의 바에 키보드 노출 처리가 없음 | 검색 입력 시 떠 있는 바가 키보드 위 공간을 과도하게 차지하지 않게 검증/처리 |

320pt 화면에서 현재 탭별 계산 너비는 `(320 - 48 - 40 - 2) / 5 = 46pt`이다. 아이콘 자체가 44pt라는 것과 탭 전체의 터치 너비는 구분해야 한다. Android 지침의 최소 48dp를 공통 터치 목표로 사용한다.

기본 글자에서 바 높이는 스타일상 약 88pt이고, 바 아래 간격 16pt를 더한 가림 높이는 약 `104 + bottom inset`이다. 기록·성장의 고정값 `100 + bottom inset`은 이 계산보다 작다. 실제 글자 확대에서는 차이가 더 커질 수 있다. 수치는 스타일 계산이며 실기기에서 겹침을 직접 재현한 결과가 아니다.

## 구현 방식 비교

| 방식 | 장점 | 제약 | 판단 |
| --- | --- | --- | --- |
| 기존 `expo-blur` + 얇은 면/테두리 | 현재 설치된 모듈 재사용, 기존 네비게이션 유지, 두 플랫폼의 형태 통일 가능 | SDK 54에서 Android 블러는 실험적. 투명한 표면의 대비를 직접 관리해야 함 | 이번 범위에 가장 적합 |
| `expo-glass-effect` | 지원되는 iOS에서 네이티브 Liquid Glass | iOS 26 이상만 지원, 미지원 플랫폼은 일반 View. 현재 미설치이므로 네이티브 빌드 변경 필요, Android/구형 iOS 표면을 별도 설계해야 함 | 향후 선택 옵션 |
| 네이티브 탭바로 전환 | OS 기본 상호작용 활용 | 현재 커스텀 탭·프로필 하위 경로·가림 높이 구조를 함께 재설계/회귀 검증해야 함 | 이번 스타일 변경의 첫 단계로는 범위가 큼 |

`BlurView`의 블러는 Apple의 굴절·상호작용을 갖는 네이티브 Liquid Glass와 동일한 효과가 아니다. Android에서 같은 굴절 효과를 보장할 수는 없지만, 크기·위치·아이콘·선택 표시·색 분위기는 일관되게 만들 수 있다.

Android는 초기 구현에서 가독성 있는 반투명 표면을 우선하고, 실제 목록 스크롤 성능과 배경 갱신을 확인한 뒤 실험적 블러 사용을 판단한다. 블러를 쓰면 동적인 콘텐츠 뒤에 렌더링되어야 하는 Expo의 제약도 확인한다. 다섯 아이콘에 별도 블러를 적용하지 않는다.

## 기기별 레이아웃 설계

1. 바 폭은 기기 모델명이 아니라 실제 사용 가능한 너비와 좌우 안전 영역으로 결정한다.
2. 일반 휴대폰에서는 다섯 칸을 같은 너비로 배치한다. 예를 들어 320pt에서 바 밖 좌우 12pt, 내부 좌우 8pt, 테두리 2pt이면 탭당 약 55.6pt를 확보할 수 있다. 값은 구현 시 터치·글자 측정으로 조정한다.
3. 각 터치 영역은 최소 48×48dp/pt를 목표로 하고 서로 겹치지 않게 한다. 큰 `hitSlop`만으로 부족한 영역을 보완하면 이웃 탭과 충돌할 수 있다.
4. 기본 바 높이 목표는 약 68~76pt로 검토하되 고정 높이를 강제하지 않는다. 이름·줄바꿈·시스템 확대 후의 실측 높이가 우선이다.
5. 큰 글자/좁은 분할 창에서는 바 외부·내부 여백부터 줄인다. 이름을 잘라내거나 시스템 글자를 임의로 축소하지 않고 줄바꿈과 높이 증가를 허용한다. 필요하면 같은 다섯 탭을 유지한 넓은 하단 도킹 형태로 전환한다.
6. 태블릿·폴더블에서는 기존 `useLayout` 크기 분류와 탭바 최대 폭 정책을 재사용한다. 작은 분할 창으로 바뀌면 즉시 좁은 화면 정책을 적용한다.
7. 화면 하단 여백은 `실측 바 높이 + 아래 간격 + bottom inset + 콘텐츠 여유`로 다섯 탭에 공통 적용한다. 이미 포함한 안전 영역은 중복 가산하지 않는다.
8. 투명도 줄이기 설정에서는 충분히 불투명한 면을 사용하고, 동작 줄이기 설정에서는 선택 전환 애니메이션을 줄이거나 없앤다. 네이티브 Liquid Glass의 자동 접근성 기능이 현재 사용자 정의 BlurView에도 자동 적용된다고 가정하지 않는다.
9. 모달·바텀시트·사진 편집기는 탭바보다 위에 있어야 한다. 최근 수정한 공통 알림의 표시 순서도 함께 확인한다.

| iPad / 폴더블 / 분할 창 | 실제 창 폭에 따른 바 최대 폭, 좌우 안전 영역 |
| 두 테마 / 사진·텍스트가 많은 배경 | 이름 대비, 비선택 아이콘 식별, 블러 갱신 |
| VoiceOver / TalkBack | 선택 상태 읽기, 탐색 순서, 아이콘 중복 읽기 방지 |
| 투명도·동작 줄이기 / 키보드 | 설정 반영, 바 높이 변화, 검색 입력과 바 위치 |
| 다섯 탭 스크롤 끝 / 모달 / 알림 | 마지막 콘텐츠와 닫기 버튼 접근, 오버레이 표시 순서 |

숫자 기반 레이아웃 검증과 컴포넌트 검증으로 범위를 줄일 수 있지만, 모든 실기기에서 문제가 없다는 결론은 실제 렌더링·OS 설정·기기 검증 없이 내릴 수 없다.

## 적용 내용 (후속 구현)

- 기존 `expo-blur`를 활용한 하나의 글래스 표면, 옅은 시안 선택 영역, 낮은 그림자로 변경했다. iOS는 블러, Android는 97% 불투명도의 반투명 표면을 사용하며 실험적 Android 블러는 사용하지 않는다.
- 선택 라벨은 밝은 테마에서 짙은 시안, 어두운 테마에서 기존 브랜드 시안으로 표시한다. 일반 라벨은 읽기 쉬운 보조 텍스트 색을 사용한다.
- 앱에서 이미 로딩하는 SUITE 이름과 로컬 Phosphor 아이콘을 사용한다. 공식 MIT 원본에서 새싹·나침반·두 사람 SVG 세 개를 추가했고 기존 라이선스 파일을 유지했다.
- 기본 바 높이 약 74pt, 안전 영역 위 간격 8pt, 탭 터치 영역 최소 48×56pt를 기준으로 구성했다. 글자 확대 시 이름을 잘라내지 않고 바 높이가 늘어난다.
- 창 폭·좌우 안전 영역·폰트 배율을 고려한다. 다섯 개의 최소 터치 영역이 들어가지 않는 극히 좁은 분할 창에서는 가로 스크롤로 탭에 접근할 수 있다. 일반 320pt 휴대폰에서는 다섯 탭이 모두 들어간다.
- 기록·성장·발견·매칭은 공통 실측 여백 훅을 사용한다. 프로필/설정은 기존 `ScreenLayout`의 실측 탭바 보호를 유지하여 호출 화면에서 지정한 더 큰 여백도 보존한다.
- iOS 투명도 줄이기는 불투명한 표면으로 전환하며 실행 중 설정 변경도 반영한다. 크기 변화 애니메이션은 없고 누름 피드백만 제공한다.
- 키보드 표시 중에는 탭바를 숨기고 닫힌 후 복원한다. 커스텀 탭 탐색의 `tabPress`/`tabLongPress` 이벤트를 연결했고 계정 관리 경로에서도 프로필 탭 선택 상태를 유지한다.
- 새 네이티브 패키지·설정 변경은 없고 백엔드·AI·인프라 소스는 수정하지 않았다. 이 변경 자체로 개발 앱 재설치는 필요하지 않다.

자동 검증: 작은 창/안전 영역/글자 배율 조합의 기하 검증, 선택/터치/길게 누르기, 실측 높이 전달, 투명도 변경, Android 블러 대체, 키보드 숨김/복원 및 기존 설정 화면 하단 접근 검증을 수행했다. TypeScript는 기존 26개 오류가 남아 있으며 이번 구현으로 추가된 오류는 없다. 실제 블러·글자 줄바꿈·OS 내비게이션 영역의 최종 육안 검증은 실기기에서 필요하다.

## 스크롤에 따른 숨김·표시 (후속 요청)

- 다섯 메인 탭의 세로 ScrollView/SectionList/FlatList에 공통 스크롤 컨트롤러를 연결했다. 프로필도 다른 네 탭과 같은 실측 하단 여백을 사용한다. 설정 화면·사진 편집·가로 추천 카드·바텀시트의 스크롤은 자동 숨김 대상에서 제외했다.
- 아래 방향 누적 이동 36pt에서 숨기고 위 방향 12pt에서 다시 표시한다. 작은 방향 변화는 누적 기준으로 걸러 깜빡임을 줄인다.
- 화면 맨 위 12pt, 맨 아래 4pt와 스크롤할 만큼 길지 않은 콘텐츠에서는 바를 표시한다. 탭 전환·창 폭/글자 배율 변경·키보드 닫힘에서도 표시한다.
- 네이티브 드라이버의 180ms 위치 전환을 사용한다. 숨김 거리는 실제 바 높이·하단 안전 영역·그림자 여유를 포함한다. 숨겨진 바는 터치와 접근성 탐색에서 제외한다.
- **숨김 때문에 콘텐츠 하단 여백을 줄이지 않는다.** 바의 위치만 이동하므로 콘텐츠 길이·현재 스크롤 위치가 갑자기 바뀌거나 끝에서 반복적으로 숨었다 나타나는 현상을 방지한다. 마지막 콘텐츠까지 스크롤하면 바가 다시 표시되며 콘텐츠가 가리지 않도록 여백을 확보한다.
- 스크롤 프레임마다 React 화면을 다시 그리지 않고, 숨김/표시 상태가 바뀔 때만 갱신한다. 관성 스크롤은 사용자 드래그에서 시작했을 때만 반영한다.
- iOS 바운스/Android 오버스크롤은 유효 범위로 제한한다. 목록 새로고침·자동 위치 복원은 숨김 동작으로 해석하지 않는다. 탭/창 크기 변경 이전 드래그는 세대 번호로 무효화하며, 비활성 탭의 늦은 이벤트도 무시한다.
- VoiceOver/TalkBack에서는 바를 항상 표시한다. 동작 줄이기 설정에서는 위치 애니메이션 없이 상태만 전환하고 실행 중 설정 변경도 반영한다.
- 드래그 종료 후 관성 시작을 기다리는 타이머와 접근성/키보드 구독을 해제하여 화면 이탈 시 작업이 남지 않게 했다.
