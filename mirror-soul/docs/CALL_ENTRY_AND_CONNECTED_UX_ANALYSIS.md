# 통화 진입·연결·영상 대화 UI/UX 분석

분석일: 2026-10-06 (한국 시간).

- RN: 최신 `origin/dev`의 PR #200 병합 커밋 `69ebec4`에서 만든 `codex/call-entry-connected-ux`.
- 백엔드: 원격 `origin/main`의 `8189275`.
- AI: 원격 `origin/main`의 `1c23863` (자연스러운 영상 전환 PR #45 포함).
- 백엔드 API 스냅샷은 실제 경로인 `.claude/artifacts/backend-schema.json`과 `analysis-report.md`를 먼저 확인했다. 이후 관련 서비스·시그널링·AI 파일을 최신 원격의 `git show`로 읽었다.
- 최초 분석 단계에서는 앱 소스·백엔드·AI·인프라를 수정하지 않고 새 브랜치와 이 문서만 만들었다. 이후 사용자 요청으로 RN만 구현했으며 후속 변경은 아래에 기록한다. 원격 fetch는 Git 참조만 갱신하며 submodule 체크아웃·포인터를 바꾸지 않았다.
- 아래 문제는 소스와 설치된 네이티브 라이브러리를 통해 확인한 결과다. 실제 서버 통화·실기기 실패 상황을 재현한 결과가 아니다. 소스의 기본값과 운영 배포 설정도 구분한다.

## 1. 현재 통화 흐름

| 순서 | 실제 처리 | UI 설계에 주는 의미 |
| --- | --- | --- |
| 통화 선택 | 발견·상세·채팅·기록·성장에서 진입. 대부분 CallStartConfirmSheet가 최신 잔여 시간을 조회 | 시작 의사는 확인 시트에서 한 번 받는다. 진입 후 다시 시작 버튼을 요구하지 않는다 |
| 마이크 권한 | `/ai-call` 진입 후 자동 시작, 마이크 권한 요청. 카메라는 기본 꺼짐 | 권한 거절은 대기 화면에 남기지 않고 기기 설정·돌아가기 경로 제공 |
| 방 생성 | `POST /calls/clones/{uuid}`, mediaType=VIDEO. REST와 로컬 WebRTC 초기화는 병렬 | 방 생성과 실제 대화 시작은 다른 단계 |
| 시그널링 | WS JOIN → JOINED → CALL_INVITE → CALL_ACCEPT | CALL_INVITE의 data는 callId만 허용. UI 상태 필드를 임의로 추가하면 서버가 거부함 |
| AI 컨텍스트 | AI가 `GET /internal/ai/calls/{id}/context`로 대상 인격·활성 음성 정보를 조회. READY/활성 음성 확인 | 미준비/서버 장애를 상대 회원이 통화를 거절한 것처럼 표현하지 않기 |
| 미디어 연결 | RN OFFER → AI ANSWER → ICE. RN은 오디오 송신·AI 영상 수신, 내 카메라는 송신하지 않음 | 양방향 사람 영상통화라는 인상을 주지 않는다 |
| 연결 판정 | RN은 ICE=connected에서 connected 표시·로컬 타이머·녹음 시작 및 PATCH in-progress 요청 | ICE 연결, 영상 초상화 준비, 실제 AI 응답 가능 상태를 동일하게 취급하면 안 됨 |
| 발화·답변 | VAD → STT → 인격/기억 조회 → LLM → TTS → Ditto 영상 → 음성·영상 큐 | 답변 전 무응답 구간은 영상 준비 지연일 수도 있음. UI가 AI의 내부 상태를 추측해 단정하지 않기 |
| 종료 | CALL_END → 로컬 녹음 중단·S3 업로드 → POST /calls/{id}/end → 로컬 미디어 정리 | 현재는 종료 탭 직후 미디어 정리/서버 정산이 끝나지 않음 |
| 후속 | 상대 트윈은 서버 종료 성공 결과로 만남 신청 화면, 내 트윈은 이전 화면 복귀 | 종료 실패 시 기록 완료·정산 성공을 표시하지 않는다 |

마이크와 스피커가 연결된 버튼이라는 점은 맞지만, iOS 음소거의 실제 네이티브 동작에는 아래 문제가 있다. 기존 주석의 ‘토글은 자리표시자’ 및 통화 텍스트 기록 TODO는 일부 최신 서버 코드와 맞지 않으므로 구현 단계에서 정리할 필요가 있다.

## 2. UI보다 먼저 해결할 동작 문제

### P0: 시간 차감 기준 불일치

RN `useAICallFlow.ts:165`는 ICE 연결 시각부터 표시 시간을 계산한다. 반면 백엔드 VideoCall 생성자는 **방 생성 시점**에 startedAt을 설정하고, `start()`는 상태만 바꾼다. `complete()`는 startedAt부터 종료 REST 처리 시점까지를 durationSec으로 계산한다. CallService.endCall은 이 시간을 차감한다.

- 연결 대기, 실제 대화, 종료 요청 전에 기다린 녹음 업로드 시간이 합쳐질 수 있다.
- 예: 방 생성 뒤 8초 연결 대기 + 60초 대화 + 6초 업로드라면 서버 계산은 약 74초, RN 표시 대화 시간은 약 60초다. 이는 코드 경로 설명용 예시이며 실측값은 아니다.
- READY 상태를 endCall로 종료해도 COMPLETE/차감 경로를 타므로 연결 전 취소를 무료라고 보장할 수 없다.
- WS CALL_END는 SignalingHandler에서 릴레이만 하며 DB의 종료 시각이나 차감을 즉시 확정하지 않는다.
- 연결 직후 PATCH 실패는 RN 로그만 남기고 계속 대화한다.

요청할 계약: createdAt·connectedAt·endedAt·billableDurationSec 분리, 연결 전 CANCELLED=0초, 종료 처리는 멱등, 업로드는 과금 종료와 분리. 연결 판정은 신뢰할 수 있는 미디어 신호/서버 확인과 소유권 검증을 포함해 결정한다. 실제 응답 가능 상태부터 과금할지 ICE 연결부터 과금할지도 제품·서버 간 통일해야 한다.

### P0: iOS 음소거가 실제 마이크를 제어하지 않음

RN `toggleMute()`는 React 상태와 InCallManager.setMicrophoneMute만 변경한다. 설치된 iOS RNInCallManager.m:286은 이 API에서 ‘지원하지 않는다’는 로그만 출력한다. Android는 AudioManager의 마이크 상태를 변경한다.

- RN에서 송신 오디오 트랙의 enabled 상태를 직접 제어하고 UI를 실제 적용 결과와 일치시켜야 한다.
- Expo 별도 통화 녹음도 있으므로 전송만 끈 상태에서 로컬 음성은 계속 녹음/업로드되는지 정책과 처리 확인이 필요하다.
- 사용자에게 ‘마이크 끄기’로 안내한다면 송신·로컬 녹음 모두 그 기대에 맞춰야 한다. 녹음 pause/resume·실패·앱 복귀·연결 재개도 검증 대상이다.
- 기존 오디오 테스트는 InCallManager 호출 여부를 주로 검증하므로 iOS 네이티브 no-op까지 보장하지 않는다.

### P1: 연결 실패·끊김·취소 복구 부족

- JOIN 단계와 OFFER/ICE 연결 단계의 별도 완료 타임아웃이 없다. 10초 제한은 CALL_INVITE에만 있다.
- AI의 컨텍스트 조회는 기본 5초 × 최대 2회 + 재시도 대기 0.2초이므로 RN의 10초 초대 제한과 충돌할 수 있다. 실제 운영값은 따로 확인해야 한다.
- WebSocket onclose는 로그만 남긴다. ICE failed/disconnected/closed는 WebRTC 훅에 저장되지만 흐름 훅은 connected 전이만 처리한다. 대화 UI·타이머가 실제 네트워크 상황과 어긋날 수 있다.
- CALL_REJECT/초대 타임아웃/일부 시그널링 오류는 `_cleanup`으로 세션 참조를 지우고, 명시적 endCall 보상 처리를 하지 않는다. 초기 REST 대기 중 취소의 보상 종료 경로와 일관되지 않다.
- 화면 unmount는 로컬 cleanup을 하지만 서버 종료·별도 녹음 마무리와 같은 정식 hangUp 경로는 아니다. Android 뒤로가기/화면 이탈/계정 변경/백그라운드 종료 정책이 필요하다.
- 재시도는 이전 callId 종료를 확인한 뒤 새 시도를 한 번만 시작해야 한다. 자동 재시도로 여러 유료 통화방을 만드는 방식은 피한다.
- 짧은 ICE disconnected에는 유예 후 상태 재확인, failed에는 종료/재시도를 제공한다. 같은 세션의 ICE 재시작을 허용할지 새로운 통화로 재시도할지 정책을 분리한다.

### P1: 내 트윈 통화의 잔여 시간 제한 전달 누락

성장의 TwinSimulationCard는 확인 시트에서 남은 시간을 읽지만 onStart 인자를 받지 않고 `/ai-call`로만 이동한다. 통화 화면은 remainingSeconds가 있어야 잔여 시간에 맞춘 자동 종료를 수행한다. 본인 통화에는 현재 이 값이 없다.

RN 수정 후보: 모든 진입점을 공통 시작 함수로 정리하고 대상 UUID·이름·최신 잔액·복귀 위치를 전달한다. 최종 자동 종료와 차감은 서버가 권위 있게 처리해야 하며 RN 라우트 값은 현재 회원이 확인한 표시용 값이다.

### P1: 종료 처리와 업로드가 결합됨

현재 `_performHangUp`은 S3 업로드를 await한 다음 종료 REST를 호출하고 마지막에 미디어를 닫는다. S3 제한은 60초이며 presigned URL 요청·종료 REST는 각각 API 타임아웃의 영향을 받는다.

- 종료 버튼은 로컬 송수신을 즉시 중지하고 ‘대화를 마쳤어요’ 상태로 전환하는 것이 좋다.
- 서버 종료·정산을 음성 파일 업로드보다 먼저 확정하고 파일은 별도의 업로드/첨부 상태로 관리해야 한다.
- 업로드 실패는 대화 종료 실패와 구분하고, 보관된 파일이 있는 경우에만 재시도한다.
- 서버의 현재 종료 API는 recordingUrl을 종료 시점에 받는 구조이며 나중 첨부하는 API가 없어 완전한 분리를 RN만으로 처리할 수는 없다.
- 종료 REST 실패는 현재 로그만 남긴 뒤 로컬 종료된다. 서버 정산 실패를 성공으로 표시하지 않는 복구 상태가 필요하다.

### P2: 녹음 포맷 및 기록 연결 확인

통화 녹음은 Expo HIGH_QUALITY로 `.m4a`/MPEG4 AAC를 만들지만 iOS 업로드 파일명/MIME은 `.wav`/audio/wav로 지정한다. 선언과 실제 포맷을 맞추는 RN 수정이 필요하다. 현재 허용 폴더 때문에 interviews 경로를 사용한다.

백엔드에는 내부 `POST /internal/ai/calls/{id}/talk-logs` 저장 API가 있다. 그러나 최신 AI의 조사한 model_calling/call_server 실시간 경로에는 해당 업로드를 호출하는 구현을 찾지 못했다. conversation_history는 세션 메모리에 있다. 별도 운영 서비스의 저장 경로 존재 여부를 확인해야 하며 ‘대화 내용이 모두 저장됐어요’는 현재 소스만으로 보장하지 않는다.

## 3. AI 대화·영상이 UI에 주는 제약

- AI 영상의 기본 송출 규격은 540×960, 25fps이며 운영 설정에 따라 바뀔 수 있다.
- 최신 AI는 정지 초상화 → Ditto 대기 루프 → 답변 영상 간 전환을 서버에서 처리한다. 대기 루프 기본 6초, 전환 기본 6프레임(0.24초). GPU/통화 서버의 실제 배포를 확인해야 한다.
- 이 변경은 화면 전환을 자연스럽게 만들며 STT→LLM→TTS→Ditto의 응답 지연을 줄이지는 않는다.
- 영상 트랙은 초상화 로드 전에도 존재하고 초기 프레임은 검은 화면일 수 있다. RN은 현재 트랙의 존재만 보고 RTCView를 표시한다. ICE 연결·트랙 생성·프레임 수신·초상화 준비를 분리해야 한다.
- 설치된 RTCView는 onDimensionsChange를 제공한다. 프레임/크기 수신 확인에는 활용할 수 있지만 내용이 정상 초상화인지나 AI 대화 준비가 됐는지는 증명하지 않는다.
- 기본 VAD는 초기 1.5초 입력 무시, 0.7초 이상 발화와 약 0.8초 침묵으로 문장을 구분하며 약 15초 발화는 잘라 처리한다. 운영 환경 변수로 달라질 수 있다.
- **AI 답변 오디오 재생 중 사용자 발화를 버린다.** 현재는 말 끊고 끼어드는 대화를 지원한다고 안내하면 안 된다. 발화 큐는 2개이며 오래된/초과 발화는 건너뛸 수 있다.
- VIDEO 모드에서 영상 생성 실패 시 기본 DITTO_CALL_AUDIO_ONLY_FALLBACK=false이므로 이미 생성된 답변 음성도 보내지 않는다. 클라이언트에서는 정상 연결인데 조용한 상태처럼 보일 수 있다.
- 단계 오류·무음/STT 빈 결과는 서버 로그에 기록되지만 대화 상태/오류 이벤트가 RN으로 전달되지 않는다. 서버 시그널링의 현재 허용 목록에도 CALL_STATE/TRANSCRIPT 등은 없다.
- 마이크가 켜짐·수신 트랙이 있음·ICE가 연결됨만으로 ‘듣는 중/생각하는 중/말하는 중’을 정확하게 표시할 수 없다. 시각적 펄스도 현재는 실제 발화에 연동되지 않는다.

## 4. 추천 UI/UX

### 시작 확인

- 기존 최신 잔액 확인 시트는 유지한다. 대상 이름 + AI 트윈 배지 + 남은 시간 + 시작 버튼을 핵심으로 두고 안내는 한 번만 보여준다.
- 프로필 사진을 사용한다면 이미 승인된 공개 프로필/기존 캐시에서 가져오고 생성된 AI 얼굴과 같은 사진이라고 표시하지 않는다.
- 시작 전 대화/녹음의 용도를 짧게 알리고 상세 안내는 선택적으로 연다. 실제 정책과 처리에 맞는 문구만 쓴다.
- 음성 입력이 필요하므로 마이크 권한은 시작 시 확인하고, 카메라는 사용자가 ‘내 모습’을 켤 때만 요청한다.

### 연결 대기

- 영어 TWIN SIMULATION·큰 펄스 오브·기술 단계 4칸 대신, 연결될 대상의 이름/사용 가능한 공개 사진과 간결한 상태 표시를 중심에 둔다.
- `연결을 준비하고 있어요` → `트윈과 연결하고 있어요`처럼 사용자에게 의미 있는 상태만 보여준다. WebRTC/SDP/ICE/모델 렌더링 단계는 노출하지 않는다.
- 연결된 뒤에도 같은 대상 정보·배경·영상 영역을 유지해 화면이 완전히 다른 장면으로 바뀌는 느낌을 줄인다. 과한 확대/펄스는 줄이고 모션 감소 설정을 존중한다.
- 오래 대기하면 ‘평소보다 연결에 시간이 걸리고 있어요’와 취소/재시도 경로를 제공한다. 완료 시각·가짜 퍼센트·AI 내부 상태를 추측해서 표시하지 않는다.
- 연결 취소는 항상 접근 가능하게 두며 실제 서버 종료 결과와 수수료/시간 안내가 일치해야 한다.

### 연결된 영상 대화

- **상단:** 상대 이름 + `AI 트윈` 배지. 경과 시간과 남은 시간은 분리하고 정산 기준을 통일하기 전에는 두 값을 같은 의미처럼 표시하지 않는다.
- **중앙:** AI 영상. 표정/말하는 영상의 전환은 서버 스트림이 담당하고 RN은 장식 효과를 추가하지 않는다.
- **하단:** `마이크` / `소리` / `내 모습` / `종료`. 상태를 알아볼 수 있는 아이콘과 짧은 이름을 제공한다. 종료만 빨간색으로 구분한다.
- 연결 성공 시 첫 인사 유도 문구를 한 번 짧게 보여주는 방향이 좋다. 단, 실제 듣기 준비 시점은 AI ready 이벤트와 맞추어야 한다. 현재는 서버가 먼저 자동 인사하지 않는 사용자 발화 기반 경로다.
- `소리`는 자동 출력·스피커 강제 선택과 실제 출력 장치의 차이를 구분한다. 현재 isSpeakerOn=false는 자동 모드이지 실제 스피커가 꺼졌다는 의미가 아니다. Bluetooth/이어폰을 자동 모드보다 아래 우선순위로 강제하지 않는다.
- 60초/마지막 10초 등 잔여 시간 안내는 서버의 과금 기준과 정책 확정 후 한 번만 제공한다. 반복 알림 소리가 마이크로 다시 들어가거나 매초 스크린리더를 방해하지 않게 한다.
- 서버 대화 이벤트가 오기 전 RN 1차 구현에서는 ‘연결됨/마이크 꺼짐/영상 준비 상태’처럼 확인 가능한 상태만 표시한다. 자막·생각 중·끼어들기 버튼은 가짜로 만들지 않는다.

### 내 모습 — 사용자 인터뷰 결정

사용자는 **내 모습 확인용으로 카메라를 유지하고 용도를 명시**하는 방식을 선택했다.

- 기본은 꺼짐. 버튼명은 ‘내 모습’, 켰을 때 ‘나에게만 보여요’를 짧게 표시한다.
- 카메라가 꺼져 있으면 빈 PIP 자리표시자를 상시 표시하지 않는다. 활성화 중에는 작은 준비 상태, 스트림 준비 후 실제 PIP를 표시한다.
- 영상은 현재처럼 AI로 보내지 않는다. 권한 안내도 ‘내 모습을 확인하려면’으로 고친다.
- PIP 탭 확대·드래그는 유지하되 실제 영상 영역의 크기에 맞춰 최소/최대 크기를 제한한다. 현재 고정 96×128/144×192와 네 모서리 계산은 짧은 가로 화면에 들어간다는 보장이 없다.
- 실제 헤더·컨트롤·안전 영역 안에서만 이동하고, 면적이 부족하면 확대를 제한하거나 축소 표시한다. 내 모습으로 상대 얼굴·이름·종료 버튼을 가리지 않도록 기본 위치를 정한다.

### 종료와 오류

- 종료 탭 직후 송수신/녹음을 끝내고, 화면에는 ‘대화를 마쳤어요’를 표시한다. 서버 정산 확인과 선택적 파일 저장 상태는 분리한다.
- 성공 시 서버의 정산 값으로 사용 시간·남은 시간을 보여준다. 상대 통화의 만남 신청과 받은 신청으로 복귀하는 기존 흐름은 유지한다.
- 재생/영상 실패는 전체 통화 실패와 구분하되 음성만 진행하는 전환은 실제 AI의 fallback 정책 지원이 있어야 한다.
- 권한 거절에는 기기 설정, 트윈 미준비에는 상태 확인/복귀, 연결 실패에는 정리 완료 후 재시도를 제공한다.
- 현재 대부분 CALL_REJECT 사유를 ‘AI 트윈이 통화를 거절했습니다’로 합친다. 준비 미완료/내부 장애를 사람의 거절로 전달하지 않도록 이유별 사용자 문구를 매핑한다.

## 5. 다양한 기기 레이아웃 원칙

- 상대 영상은 기본 9:16이지만 실제 수신 크기를 사용한다. 무조건 전체 화면 cover로 잘라내지 말고 영상 영역에서 contain을 기본으로 하여 얼굴·어깨가 보이게 한다.
- 남는 공간은 앱의 기존 어두운/밝은 배경과 옅은 시안·퍼플로 처리한다. 영상 대비 때문에 필요한 중립 어두운 영역은 브랜드 색 과장과 구분한다. 글꼴은 앱의 SUITE/Pretendard 체계를 재사용한다.
- 세로: 상단 정보·중앙 영상·하단 조작의 3영역. 연결 대기와 통화 중 모두 같은 틀을 사용한다.
- 가로: 세로 영상을 억지로 늘리지 않고 영상/정보와 조작 레일을 나누는 구성을 검토한다. 종료 버튼과 이름의 글자 확대를 우선 보장한다.
- 영상 영역은 남은 공간을 사용하고 chrome 높이는 실제 onLayout으로 계산한다. 글자 확대 시 이름·상태는 필요한 줄로 늘어나며 영상/PIP가 줄어든다.
- 전화·마이크 등 핵심 버튼은 최소 48px 터치 영역. 아이콘만으로 켜짐/꺼짐을 전달하지 않고 selected/disabled/busy 접근성 상태와 명확한 이름을 제공한다.
- 일반 통화에서는 스크롤 없는 사용을 목표로 한다. 연결 오류의 긴 안내·큰 글자·종료 후 신청 화면은 스크롤을 허용하고 마지막 버튼을 잘라내지 않는다.
- Android RTCView의 SurfaceView z-order, React 오버레이·PIP 겹침·터치 우선순위를 실제 기기로 확인해야 한다. native view 레이어는 보통 View의 zIndex와 같다고 가정하지 않는다.
- 앱 백그라운드/잠금에서 통화를 유지하는 것은 단순 UI 변경이 아니다. 플랫폼 권한·오디오 세션·서버 만료 정책을 확인한 뒤, 초기에는 백그라운드 중 통화 상태를 숨기거나 무기한 과금되는 흐름부터 막는다.

## 7. 다음 구현 순서와 확인 기준

1. RN의 통화 생명주기·실제 음소거·시간 전달·종료 실패 처리부터 보완하고 백엔드에 정산 기준을 공유한다.
2. 현재 제공되는 상태만 사용해 연결 대기와 영상 대화 레이아웃을 통일한다. 카메라는 내 모습 확인용으로 유지한다.
3. 서버 계약이 확정되면 남은 시간·응답 상태·영상 실패 안내·선택 자막을 연결한다.
4. 실기기에서 iPhone/Android, 320×568, 일반/큰 화면, 가로, 글자 배율 1/1.3/2, 긴 닉네임을 확인한다.
5. 권한 최초 허용/거절/설정 복귀, 연결 각 단계 취소, AI 미준비, 느린 내부 컨텍스트 요청, Wi-Fi→셀룰러 전환, Bluetooth 연결/해제, 앱 이탈/복귀를 확인한다.
6. 음소거 후 AI 송신과 로컬 녹음에 실제 음성이 남지 않는지, 0초 자동 종료가 내 트윈·상대 트윈에서 동일한지 검증한다.
7. 종료 중 느린 업로드/실패/종료 API 타임아웃, 기록 저장 실패, 빠른 연속 시작/종료, 만남 신청·받은 신청 복귀 흐름을 확인한다.

최초 분석에서는 테스트를 추가하거나 새로 실행하지 않았다. 네이티브 음소거와 시간 차감 관련 결과를 기존 mock 테스트가 재현했다고 표현하지 않는다.

## RN 구현 결과 (2026-10-06)

- 연결 대기는 대상 이름과 AI 배지·간결한 연결 상태·취소 버튼으로 정리했다. 기존 과한 펄스/오브/기술 단계 표시를 제거하고 앱의 SUITE/Pretendard·옅은 시안/퍼플·중립 배경을 재사용한다.
- 통화 중 상단 정보, 중앙 영상, 하단 4개 조작(마이크/소리/내 모습/종료)을 분리했다. 영상은 contain으로 유지하고 가로 화면에서는 조작을 옆 레일에 배치한다. 짧은 화면의 큰 접근성 글자는 전체 스크롤로 전환하며 조작 영역과 긴 안내도 스크롤로 마지막 동작에 접근할 수 있다.
- 내 모습은 기본 꺼짐이며 켰을 때만 PIP를 표시한다. 실제 영상 영역을 측정해 크기·모서리를 제한하고 ‘나에게만’ 안내를 제공한다. 큰 글자에서는 겹치기 쉬운 PIP 내부 안내 대신 조작 영역의 안내를 사용한다. AI로 카메라를 전송하지 않는다.
- iOS no-op인 InCallManager 음소거에 의존하지 않고 WebRTC 송신 오디오 트랙의 enabled를 제어한다. 별도 녹음도 pause/resume하며, mute 준비/녹음 준비의 순서가 뒤바뀌어도 음소거 중 녹음을 시작하지 않는다. pause 등 제어 실패 시 해당 녹음을 폐기하고 통화를 종료하여 의심되는 음성이 업로드되지 않게 한다.
- 초기화 이후 늦게 도착한 마이크·카메라와 이전 peer의 이벤트를 무시한다. StrictMode의 effect 재실행은 마이크/통화를 잘못 종료하지 않도록 실제 unmount 여부를 microtask에서 확인한다.
- 준비·JOIN·초대·ICE 연결에 타임아웃을 두고, 잠깐 끊긴 ICE에는 5초 복구 유예를 제공한다. WebSocket close/error 및 연결 실패도 기존 callId를 종료하는 경로로 정리한다. AI 미준비를 사람의 통화 거절로 표현하지 않는다.
- 연결 완료 PATCH가 실패하면 성공한 통화처럼 계속 진행하지 않고 종료 확인을 시도한다. 서버의 signalingUrl을 사용하며 현재의 엄격한 CALL_INVITE 필드 계약은 유지한다.
- 종료/취소를 누르면 송신 트랙·peer·카메라·통화 오디오를 먼저 정리한다. 서버 종료에 실패하면 같은 callId로 종료 확인을 재시도하고, 종료되지 않은 방을 둔 채 새 방을 시작하지 않는다. 백그라운드 통화 유지 정책을 임의로 변경하지 않으며 앱 복귀 시 실제 시각으로 경과 시간을 갱신한다.
- 통화 파일을 HIGH_QUALITY 실제 포맷인 .m4a/audio/mp4로 통일했다. 파일 업로드 전·URL 발급 후 계정 소유권을 확인한다. 현재 지원되는 interviews 디렉터리는 유지한다.
- 성장의 내 트윈 통화에도 최신 잔액을 전달해 다른 진입점과 같은 자동 종료 경로를 사용한다. 연결 실패 후 수동 재연결은 잔액을 다시 조회하고, 0초/조회 실패/계정 변경이면 새 통화로 진입하지 않는다. 권한을 기기 설정에서 바꾼 뒤 같은 오류 화면에서 재연결할 수 있다.
- Android 뒤로가기는 정식 hangUp을 사용하며 iOS 통화 화면 스와이프 이탈을 막았다. 연결 전 취소 중에는 대화 화면의 조작 버튼이 갑자기 나타나지 않는다. 기존 상대 통화 종료 후 만남 신청·받은 신청 복귀는 유지한다.
- 영상 트랙 존재와 실제 영상 크기 수신을 분리하고 수신 전에는 이름 기반 placeholder를 표시한다. onDimensionsChange는 검은 프레임/정상 초상화/AI 응답 readiness의 보증이 아니므로 실제 AI 상태 이벤트는 만들지 않았다.

### 서버 협의가 여전히 필요한 부분

1. **과금:** 방 생성 시각 기준 계산은 변경하지 못했다. RN 안내에서 ‘연결 뒤부터만 차감’ 약속을 없애고 종료 후 정산 값은 ‘정산 기준 시간’으로 표시한다. 연결 전 취소도 무료라고 표시하지 않는다.
2. **종료와 저장 분리:** 로컬 소리/영상은 즉시 끄지만 현재 API에 녹음 후속 첨부 계약이 없으므로 파일 업로드 후 종료 REST 순서는 남아 있다. 실제 정산은 업로드 지연의 영향을 받을 수 있다. 업로드 실패·앱 강제 종료·REST 응답 유실에도 서버가 정산/만료를 확정하는 계약이 필요하다.
3. **대화 상태:** 듣는 중/답변 준비/말하는 중/영상 생성 실패/끼어들기를 정확히 보여주거나 지원하는 이벤트는 추가하지 않았다. 현재 서버가 허용하지 않는 메시지를 보내지 않는다.
4. **서버 강제 종료:** RN의 잔액 기반 자동 종료는 보조 기능이다. 백그라운드 suspend·앱 강제 종료·네트워크 상실·동시 통화까지 서버가 만료 시각으로 강제 종료해야 한다.

### 실기기 우선 확인

- iPhone/Android에서 음소거 중 AI가 실제 발화를 받지 않는지, 저장된 파일에 음소거 구간의 사적인 발화가 포함되지 않는지.
- 연결 각 단계 취소·권한 거절→설정→재연결·서버 거절·Wi-Fi/셀룰러 전환·종료 API 실패와 재시도.
- 내 트윈/상대 트윈의 시간 제한·재연결 잔액 갱신·만남 신청/받은 신청 복귀.
- 세로/가로·320×568·큰 글자·긴 닉네임, 내 모습 확대/축소/드래그·Android RTCView 레이어와 버튼 터치.
- 영상 표시 전 placeholder→영상 전환, 실제 출력 장치의 자동 모드/스피커/이어폰/Bluetooth, 작은 통화 음성 키우기 설정 유지.

자동 테스트와 번들 생성은 위 네이티브·실제 배포 서버 검증을 대신하지 않는다.

### 최종 자동 검증

- 전체 Jest 102개 묶음·691개 테스트 통과 (`--runInBand --forceExit`; 기존 Sentry SDK 타이머로 종료 옵션 사용).
- 변경 소스·테스트 ESLint 통과. 전체 tsc에는 기존 오류 26개가 남아 있지만 이번 변경 파일에는 오류가 없다.
- iOS·Android Metro/Hermes 번들 생성 및 git diff 공백 검사 통과.
- 패키지/네이티브 설정은 바꾸지 않았다. 기존 개발 앱에서 Metro 새로고침으로 JS 변경을 확인할 수 있다.
- 실제 기기 레이아웃·음소거 녹음 내용·출력 경로·배포 서버의 과금/종료는 직접 검증하지 않았다.

### 영상 양옆 흰 여백·기기별 배치 후속 개선

- 연결된 통화/미리보기만 앱의 기존 darkTheme을 적용한다. 영상 주변의 밝은 카드 배경·좌우 padding·테두리를 제거하고 영상과 바깥 배경을 같은 #141414로 이어준다. 전체 앱 테마·연결 대기·오류·종료 후 화면은 사용자 테마를 유지한다. 상태바는 해당 화면의 명암에 맞춘다.
- 영상은 contain을 유지해 다른 종횡비에서 얼굴·어깨를 잘라 채우지 않는다. 영상 비율 때문에 남는 공간은 통화 배경과 같은 어두운 색으로 처리한다. 원본 영상 자체의 내용/색은 RN에서 수정하지 않는다.
- 조작 영역의 실제 폭이 좁으면 2열로 전환하고, 280px 미만의 창·큰 접근성 글자·짧은 화면은 스크롤 fallback으로 모든 행동에 접근할 수 있다. 영상과 내 모습 미리보기는 기존 실제 영역 측정과 경계 제한을 유지한다.
- 후속 검증: 관련 2개 Jest 묶음·21개 테스트 통과(240/320/740/1024px 조건, 큰 글자, 미리보기 경계), 변경 파일 ESLint 통과, 변경 파일 새 타입 오류 없음, iOS·Android Metro/Hermes 번들 생성 통과. 실제 Yoga 배치·기기 영상 레이어는 실기기 확인이 필요하다.

### 내 모습 미리보기 애니메이션 제거

- 위치·크기 전환의 spring/timing을 제거했다. 탭 확대/축소·화면 크기 변경·드래그 종료 시 위치와 크기를 즉시 적용한다. 드래그 기능과 영역 제한은 유지하며 같은 모서리에서 드래그해도 놓으면 바로 정렬된다. 관련 21개 테스트와 변경 파일 ESLint가 통과했다.
