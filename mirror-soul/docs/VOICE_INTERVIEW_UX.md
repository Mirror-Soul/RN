# 회원가입 음성 인터뷰 UI/UX 개편

작업 브랜치: `codex/onboarding-voice-interview-ux`
기준: 프로필 사진 PR #190의 커밋 `f57864c`에서 시작했고, 최신 `origin/main`(`26b2dda`)을 `b4b3c62`로 병합했다.

현재 원래 작업 디렉터리의 `codex/onboarding-voice-interview-ux`에서 구현·검증한다. 변경 범위는 RN이다. 백엔드·AI·인프라, 패키지 의존성, 네이티브 설정은 바꾸지 않았다. 기존의 다른 로컬 변경사항은 보존한다.

## 사용자 흐름

1. ‘트윈에게 내 이야기를’과 실제 서버 질문 수·전체 예상 시간을 보여준다. 5문항이면 약 2~3분이며, 개수가 달라지면 안내도 바뀐다.
2. 질문을 먼저 읽고 ‘상황·내 행동·이유’를 짧게 말하도록 안내한다. ‘말문이 막힌다면’ 도움말은 선택해서 펼친다. 서버 질문 자체는 유지한다.
3. 주요 버튼은 화면 아래에 고정한다. 큰 장식 파형을 없애고 실제 입력 음량·녹음 시간을 작게 표시한다. 실시간 자막은 원하는 사용자만 펼친다.
4. ‘녹음 마치고 확인’은 녹음 종료만 수행한다. 답변을 자동 업로드하지 않는다.
5. 같은 화면에서 최종 문장을 확인하고 ‘답변 저장하고 다음’을 누른다. 해당 녹음에서 인식된 발화가 있을 때만 문장 수정을 제공한다. 녹음 듣기는 선택이며, 필수 전체 재생·별도 확인 Modal은 없다.
6. 인식 오류·중단이 있었다면 재녹음을 먼저 권한다. 파일과 인식된 발화가 있고 내용이 맞다면 ‘내용 확인 후 저장’으로 계속할 수 있다. 무음 또는 인식된 발화가 없는 녹음은 문장 수정·저장을 차단하고 재녹음을 안내한다. 실제로 말했어도 인식 결과가 없다면 다시 녹음해야 한다.
7. 전송 준비·실제 전송량·서버 저장을 구분해서 표시한다. 실패한 답변은 화면에 유지한다. PUT 성공 뒤 POST가 실패했다면 같은 녹음 식별자의 파일은 다시 전송하지 않고 등록만 재시도한다. 다시 녹음한 답변에는 새 식별자를 부여해 새 음성을 업로드한다.

## 문구·접근성

- ‘AI 인터뷰어’ 장식 대신 ‘이번에 나눌 이야기’와 실제 질문을 중심으로 보여준다.
- ‘평소 내 모습에 가까운 답이면 충분해요’, ‘생각할 시간이 필요하면 잠깐 쉬어도 괜찮아요’로 부담을 줄인다.
- 비슷한 경험이 없을 때는 자신이라면 어떻게 할지와 이유를 말해도 괜찮다고 안내한다. 특정 성격이나 정답을 유도하지 않는다.
- ‘기기 내에서만 처리’ 문구를 제거하고 오디오·답변이 서버로 전송되어 트윈 음성·프로필 생성에 쓰인다고 안내한다.
- 공통 테마·서체·간격을 사용한다. 고정폭 다음 버튼을 제거하고, 버튼·답변 액션·진행 표시가 큰 글씨에서 줄바꿈할 수 있게 한다.
- 마이크와 음성 인식 권한을 함께 설명한다. 영구 거절에만 설정 진입을 제공하고, Android 뒤로가기로 Modal을 닫을 수 있다.

## 흐름 안정성

- 준비/시작/녹음/종료/확인/저장을 나누고, state 반영 전에도 동기 잠금으로 연타를 막는다.
- 인식 결과는 최신 ref에서 읽는다. 동일 이벤트 묶음의 최종 결과와 종료가 마지막 말을 잃지 않도록 하고, 중복 stop은 하나의 Promise로 처리한다.
- 종료 timeout에서는 native 인식을 중단하고 내용을 확인하게 한다. 이전 native 세션이 아직 종료 중이면 새 인식을 시작하지 않는다.
- 인식 조기 종료·녹음 오류·앱 background·화면 이탈에는 현재 녹음을 마치고 확인 대상으로 남긴다. 재생도 화면 이탈/앱 background/저장 중 멈춘다.
- 파일 없음·빈 파일, 잘못된 질문 ID, 빈 답변은 서버 전송 전 차단한다. 짧은 문장을 음질 불량으로 오판하는 기존 5글자 차단은 제거했다.
- 녹음에서 인식된 원문과 수정된 문장을 분리한다. 원문이 없으면 화면·수정 함수·저장 함수·업로드 함수에서 차단하며, 직접 입력한 문장은 발화의 근거가 될 수 없다. 재녹음은 이전 발화 근거를 이어받지 않고, 인식 종료 실패 시 화면에 남은 이전 자막도 재사용하지 않는다. 원문은 RN 내부 검증에만 사용하고 서버 DTO는 유지한다.
- 제출은 사용자·질문·파일·답변을 고정하고 세션 전환 후 이전 파일을 다른 계정에 등록하지 않는다.
- 매번 녹음 옵션을 명시하여 iOS에서도 새 파일 경로를 생성한다. 재녹음 시작·종료 실패 시 기존 답변의 문장과 음성 파일을 함께 보존한다. 녹음 시작 자체가 실패하면 준비된 녹음기도 정리해 재시도를 허용한다.
- 로그인 여부·계정 변경 시 진행 상태와 이전 답변을 비우고 로그인 확인을 안내한다. 작업 세대 번호로 이전 녹음·저장 결과를 무시하며, 같은 계정의 토큰 갱신은 인터뷰를 중단하지 않는다.
- STT 종료 호출이 예외를 던져도 듣기·종료 상태를 정리하고, 부분 문장을 보존한 채 native 인식 중단을 시도한다.
- 서버 응답의 `saved`와 문항 ID를 확인한 뒤 진행한다. 가입 상태 제한 오류는 임의로 성공 처리하지 않고 재로그인으로 진행 상태를 확인하는 동작을 제공한다.
- 저장이 화면을 벗어난 동안 성공하면, 같은 화면으로 돌아왔을 때 다음 단계 처리를 한 번만 한다.
- 질문 로딩·실패·빈 결과를 구분하고 fallback 문항 ID로 녹음·저장을 시작하지 않는다.

## 구현하지 않은 범위

주변 대화·잡음의 종류·본인 화자·질문 관련성·사실 여부를 자동 판별하는 기능은 아니다. 현재 경고는 native 인식 실패·조기 종료·중단 및 인식 문장 부재에 근거한다. Meter는 입력 크기만 보여주며 잡음 판정 점수로 쓰지 않는다. 문장을 고쳐도 녹음에 섞인 주변 목소리가 없어지지 않으므로 이 경우 재녹음을 권한다.

앱 종료 후 draft 재개, 교차 기기 진행 복원, 서버 질문 수 변경, 자유 꼬리 질문 저장은 추가하지 않았다. 같은 화면에서 재시도하는 동안의 답변 보존을 제공한다. 공용 STT 훅의 기존 함수 이름과 반환 텍스트 계약은 유지해 목소리 성장 화면에서도 사용할 수 있다.

## 검증과 실기기 확인

새 테스트는 최종 인식/종료 경쟁, 중복 stop·save, 실패 답변 유지, 선택 문장 수정·재생, 인식 경고 후 저장, 계정 전환, 잘못된 서버 질문, 서버 저장 응답 검증과 화면 복귀 후 진행을 다룬다. 파일 경로 재사용 후 재녹음 업로드, 녹음 파일 분리, 준비된 녹음기 정리, 세션 변경 도중 시작·종료·저장 복구, 같은 계정의 토큰 갱신, STT 종료·중단 예외, 목소리 업데이트 오류 복구와 연타 방지를 추가했다. 무음·빈 인식 결과의 수정/저장 차단, 직접 입력한 답변의 업로드 차단, 무음 재녹음 후 정상 발화로 복구, 원문을 유지한 오타 수정도 검증한다. 전체 **27 suites/176 tests 통과**, 변경 파일 **ESLint 오류·경고 0개**, 변경 파일의 **새 타입 오류 0개**다. 프로젝트 전체 tsc에는 기존 SVG·라우팅 등의 오류가 남아 있어 전체 성공으로 보고하지 않는다. 기존 Sentry 테스트 타이머로 인한 Jest 종료 경고는 남아 있다.

실제 iOS/Android의 녹음·재생·권한과 작은 화면/큰 글씨/키보드 배치는 기기 확인이 필요하다. Apple Silicon iOS 시뮬레이터와 앱 전체 웹 실행은 저장소에 기록된 native 의존성 제한 때문에 검증 경로로 사용하지 않았다.

기존 개발 앱에서 확인할 때 저장소 루트에서 아래 명령으로 현재 브랜치의 RN 디렉터리에 들어가 Metro를 실행한다. 이미 다른 작업의 Metro가 실행 중이면 별도 포트를 사용한다.

```bash
cd mirror-soul
npx expo start --dev-client --port 8082
```

이번 변경 때문에 prebuild/Pods 재설치를 할 필요는 없다. 기존 설치된 의존성을 그대로 사용한다.

## 실기기 피드백: 기존 화면 복원 및 전환 오류

스크롤을 줄이기 위해 적용했던 소개·여백 축소, 버튼 가로 배치와 답변 접기는 되돌렸다. 원래 인터뷰 화면의 문구·간격·세로 버튼과 답변 전체 표시를 유지한다.

‘다음’ 또는 ‘다시 녹음’으로 재생 컴포넌트가 사라질 때, `useAudioPlayer`의 native 객체 해제 뒤 focus effect 정리에서 `pause()`를 호출하는 오류를 재현했다. 플레이어마다 layout effect에서 먼저 활성 여부를 표시하고, 해제 이후에는 native 메서드를 호출하지 않도록 했다. 화면만 벗어나고 컴포넌트가 유지되는 경우에는 재생을 정상적으로 일시정지한다. 지연된 재생 준비가 화면 전환 뒤 끝나더라도 해제된 파일을 재생하지 않는다.

## 공용 STT 소비 화면의 복구

목소리 업데이트 화면도 녹음 준비 상태와 동기 잠금으로 연타를 막는다. 파일 녹음 후 STT 시작에 실패하면 두 작업을 종료하고 초기 화면으로 돌아간다. 종료는 두 작업 모두 정리될 때까지 기다리고, 어느 쪽이 실패하든 학습 요청을 보내지 않으며 다시 녹음할 수 있게 한다. 화면 제거 후 지연된 준비·종료 결과가 오면 녹음 시작·학습 전송·완료 표시를 이어가지 않는다. 기존 레이아웃을 유지하며 준비 중 안내만 추가했다.
