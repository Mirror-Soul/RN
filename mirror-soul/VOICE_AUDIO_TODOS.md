# 음성 및 오디오 화면 (추후 진행 사항 정리)

본 문서는 현재 UI 상에서 제외되었거나, 백엔드/AI 파트와의 협의가 필요한 '음성 및 오디오' 관련 남은 작업들을 정리한 문서입니다.

---

## 1. 상대방 말하기 속도 적용 (API 연동)

**현재 상태**:
- 프론트엔드 UI(세그먼트 컨트롤) 구현 완료.
- 사용자가 선택한 속도 값(`slow`, `normal`, `fast`)은 Zustand + SecureStore를 통해 기기에 영속적으로 저장됨.

**추후 진행할 작업**:
- [ ] **AI 개발자 협의**: 통화 시작(`CALL_INVITE` 등) 시 전달할 파라미터 명세 확정. (예: `speechSpeed: 0.8 | 1.0 | 1.25` 등 수치로 변환할지, 문자열 그대로 넘길지 결정)
- [ ] **프론트 연동**: `useAICallFlow.ts` 혹은 통화 진입 지점에서 `useVoiceAudioStore.getState().speechSpeed` 값을 가져와 웹소켓(시그널링) 혹은 API 요청 페이로드에 포함하여 전송.

---

## 2. 상대방 목소리 크기 조절 (볼륨 조절)

**현재 상태**:
- 기획 상에는 있었으나, 프론트엔드에서 React Native WebRTC 스트림의 볼륨 증폭(`GainNode`)을 독립적으로 제어하기 불가능하여 UI 및 기능에서 임시 제외됨. (React Native는 Web Audio API를 지원하지 않으며, 현재 도입된 라이브러리 `expo-audio`로는 실시간 WebRTC 스트림 볼륨 조절이 불가능함)

**추후 진행할 작업 (회의 안건)**:
- [ ] **해결 방향 논의**: 상대방 볼륨 조절을 구현하려면, 프론트가 아닌 **AI/백엔드 서버에서 TTS 음성 출력의 Gain(데시벨/볼륨)을 조절한 뒤 송출**하는 방식으로 해결해야 합니다.
- [ ] **기획/UX 결정**: 해당 기능을 서버에서 처리할지, 아니면 스마트폰 하드웨어 볼륨키 조절에만 전적으로 의존하고 앱 내 UI에서는 영구적으로 뺄 것인지 결정.
- [ ] (서버 처리로 결정 시) UI 슬라이더 컴포넌트를 다시 살리고, 선택된 볼륨 값(예: 0~100%)을 통화 시작 파라미터에 포함하여 서버로 전송.

---

## 3. 오디오 권한 및 상태 엣지케이스 처리 (옵션)

**현재 상태**:
- `expo-audio` 및 WebRTC를 통한 기본 통화는 문제 없이 작동 중.

**추후 진행할 작업**:
- [ ] 사용자가 통화 중이거나 백그라운드에 진입했을 때 오디오 라우팅(스피커폰 vs 수화기) 변경 대응 및 설정 UI 추가 여부 논의.
